# VirtualBareMetal98

PC-98x1 の MS-DOS 上で動く仮想 PC-98。フロッピーディスクから直接起動するアプリ（OS を介さない
ベアメタルアプリ）を、実機の PC-98x1 で、ディスクイメージファイルから動かす。

A virtual PC-98 that runs on MS-DOS on a real PC-98x1 (80386 or later). It boots floppy-based
bare-metal software from disk image files, using the host's own hardware and ROM BIOS.

## 仕組み

CPU を仮想86モードにし、その中に PC-9801VM 相当の仮想 PC-98 を作る。表示・音・キーボードなどの
ハードウェアと ROM BIOS はホストの実物をそのまま使い、FDD の BIOS 呼び出し（INT 1Bh）だけを横取りして
イメージファイルの内容で応える。サイクル正確性（実行速度、タイミング）は担保しない。

| 項目 | ゲストに見せる構成 |
| --- | --- |
| メインメモリ | 640KB。ホストの下位メモリとは別に確保する |
| FDD | 2 台（ドライブ 0・1）。中身はホスト上のイメージファイル |
| HDD | なし。ホストの HDD はゲストに見せない |
| メモリスイッチ | 起動時のホストの値。オプションで上書きできる。ホストのスイッチは変えない |
| 表示・音・キーボード・タイマ | ホストの実物 |

## 開発状況

開発中。動作確認は PC-98 エミュレータ NP21/W の上で行っていて、実機では未確認。

NP21/W 上で確認している範囲:

- 合成イメージによる自動試験（ディスクイメージ層、INT 1Bh の意味論、モニタ核、起動、スクリーンショット、VM メニュー）
- 市販ゲームのイメージ 3 本（NFD 形式）。ソーサリアン（PROGRAM ディスク）はメインメニュー、イース1 はタイトル、
  イース2 はオープニングデモまで進む。その先（ゲーム本編、ディスク交換）は未確認

まだ動かないもの:

- V30 エミュレーション（`-v30` は受け取るだけ）
- DIP スイッチの差し替え（`-dipsw` は受け取るだけ）
- CPU リセットからの再起動（いまは MS-DOS に戻る）
- 機種判別フラグの PC-9801VM 化（ホストの値のまま）

## 動作環境

- 80386 以上の CPU を搭載した PC-98x1
- MS-DOS。CPU がリアルモードであること（EMM386 などの仮想86モニタが常駐していないこと）
- XMS ドライバ（HIMEM.SYS など）。ゲストのメモリを XMS から確保する

## 使い方

```
VBM98 [-fdd0 <ファイル>] [-fdd1 <ファイル>] [-v30 on|off] [-dipsw <16進6桁>] [-memsw <16進16桁>] [-ss <名前>]
```

| オプション | 内容 | 省略時 |
| --- | --- | --- |
| `-fdd0 <ファイル>` | ドライブ 0 にイメージを入れる。起動はこのドライブから | 起動前にファイル選択を開く。取り消したら終了する |
| `-fdd1 <ファイル>` | ドライブ 1 にイメージを入れる | 空（ディスクなし） |
| `-v30 on` / `-v30 off` | V30 エミュレーションの有効・無効（未実装。受け取るだけ） | `on` |
| `-dipsw <16進6桁>` | DIP スイッチ SW1・SW2・SW3 の値を、この順に 2 桁ずつ（未実装。受け取るだけ） | ホストの現在値 |
| `-memsw <16進16桁>` | メモリスイッチ 8 個の値を、1 番から順に 2 桁ずつ。ゲストにだけ作用し、ホストのメモリスイッチは変えない | ホストの現在値 |
| `-ss <名前>` | スクリーンショットのファイル名の先頭（4 文字まで。英小文字は大文字にする） | ドライブ 0 に最初に入れたイメージのファイル名の先頭 4 文字 |

- オプション名と値の大文字・小文字は区別しない。同じオプションを繰り返したら後のものが有効
- イメージが開けないときはメッセージを出して終了する
- 起動時にホストのメモリスイッチの値（8 バイト）を表示する。`-memsw` の値はそれを元に組む

```
VBM98 -fdd0 GAME.NFD
VBM98 -fdd0 DISK1.FDI -fdd1 DISK2.FDI -ss GAME
VBM98 -fdd0 GAME.NFD -memsw 480504080100006E
```

3 つ目は、ホストの値が `48 05 04 00 01 00 00 6E` のときにメモリスイッチ 4 の bit 3 だけを立てる例。

### ホットキー

ゲストの実行中に効く。

| キー | 動作 |
| --- | --- |
| CTRL + GRPH + DEL | VM メニュー（仮想マシンのメニュー）を開く。下の 4 つを選べる |
| CTRL + GRPH + テンキーの 0 | ドライブ 0 の取り出し・入れ替え（イメージファイルの選択） |
| CTRL + GRPH + テンキーの 1 | ドライブ 1 の取り出し・入れ替え（イメージファイルの選択） |
| CTRL + GRPH + COPY | スクリーンショットの保存 |
| CTRL + GRPH + STOP | 仮想マシンの終了（問い合わせの後） |

- メニューとファイル選択のあいだゲストは一時停止し、画面は退避してから復元する
- ファイル選択の一覧には .fdi .nfd .fdd .hdm .img を出す。全ファイルの表示に切り替えられる
- ゲストが割り込み禁止のまま HLT で止まったとき（アプリが自分で終了したとき）も VM メニューが開く
- 終了すると MS-DOS のプロンプトに戻る

### スクリーンショット

表示中のグラフィック画面とテキスト画面を別々の PNG にして、ホストのカレントディレクトリへ保存する。
ファイル名は `<名前>###G.PNG`（グラフィック）と `<名前>###T.PNG`（テキスト）。`<名前>` は `-ss` の値、
`###` は 001 から 999 で空いている最小の番号。

- グラフィックは 640×400（200 ラインの画面は縦 2 倍）。8 色モードならデジタルパレットの 8 色、
  16 色モードならアナログパレットの 16 色
- テキストは 640×400 で、文字のない画素を透明にする

### 対応ディスクイメージ

| 形式 | 由来 | 拡張子の例 |
| --- | --- | --- |
| FDI | Anex86 | .fdi |
| NFD r0 / r1 | T98-Next | .nfd |
| FDD | Virtual98 | .fdd |
| RAW（ヘッダなし） | SL9821 など | .hdm ほか |

形式は拡張子ではなくファイルの中身で判定する。RAW として受け付けるサイズは 1.25MB / 1.21MB / 1.44MB /
720KB / 640KB の 5 種。書き込みは BIOS 呼び出しのたびにイメージファイルへ反映する。

### 対象外

- FDC を BIOS を通さず直接操作するアプリ

## ビルドと試験

ビルドは Linux 上の gcc-ia16（`ia16-elf-gcc` と libi86）で行う。Windows では WSL を使う。
道具の入れ方と試験の実行環境の指定は [docs/setup.md](docs/setup.md)。

| コマンド | 内容 | 要るもの |
| --- | --- | --- |
| `sh tools/build16.sh` | DOS 向けのビルド。`build/dos/VBM98.EXE` ができる | gcc-ia16、Python 3 |
| `python tests/run_host_tests.py` | ディスクイメージ層と INT 1Bh の意味論をホスト OS 上で試験する | gcc、Python 3 |
| `python tests/run_dos_tests.py` | 16 ビット版のディスクイメージ層、モニタ核、起動、スクリーンショット、VM メニューを DOS 上で試験する | 上のビルド結果、DOSBox か NP21/W |

試験は仕様書から自作した合成イメージで行う。実物のディスクイメージはリポジトリに入れない。
