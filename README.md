# VirtualBareMetal98

PC-98x1 の MS-DOS 上で動く仮想 PC-98。フロッピーディスクから直接起動するアプリ（OS を介さない
ベアメタルアプリ）を、実機の PC-98x1 で、ディスクイメージファイルから動かす。

A virtual PC-98 that runs on MS-DOS on a real PC-98x1 (80386 or later). It boots floppy-based
bare-metal software from disk image files, using the host's own hardware and ROM BIOS.

## 仕組み

CPU を仮想86モードにし、その中に PC-9801VM 相当の仮想 PC-98 を作る。表示・音・キーボードなどの
ハードウェアと ROM BIOS はホストの実物をそのまま使い、FDD の BIOS 呼び出し（INT 1Bh）だけを横取りして
イメージファイルの内容で応える。サイクル正確性（実行速度、タイミング）は担保しない。

| 項目 | ゲストに見せる構成 |
| --- | --- |
| メインメモリ | 640KB。ホストの下位メモリとは別に確保する |
| FDD | 2 台（ドライブ 0・1）。中身はホスト上のイメージファイル |
| HDD | なし。ホストの HDD はゲストに見せない |
| メモリスイッチ | 起動時のホストの値。オプションで上書きできる。ホストのスイッチは変えない |
| 表示・音・キーボード・タイマ | ホストの実物 |

## 開発状況

開発中。動作確認は PC-98 エミュレータ（NP21/W と DOSBox-X）の上で行っている。

実機での結果（利用者からの報告。v0.1.23 まで）:

- PC-9821Cr13: FreeDOS(98)・MS-DOS 6.2・Windows 98 の DOS のどれをホストにしても、MS-DOS などのディスクが起動し、
  キーボードも効く。ディスク版の N88-BASIC(86) と、市販ゲームの体験版 2 本（NFDMAKE で吸い出した NFD）が動き、FM 音源の
  音も正常に鳴る。EMM ドライバ（VCPI）の下でも、ほとんどの場合は動く。ホストに AutoMATE を常駐させていても、ゲストで
  キーが効く（30 行 BIOS は、MS-DOS 6.2 のホストなら効く）
- PC-9821Ap2（486、MS-DOS 6.2、EMM386.EXE に `/DPMI`）: 市販ゲーム 2 本が起動し、FM 音源の音も鳴る。ゲストがディスクを
  読む間、ホストのディスクにはほぼアクセスしない。ホットキーで開く VM メニューと終了の確認が使える（12 回続けて開いて、
  毎回キーが効いた）。続けて別のソフトを起動しても、前のソフトの絵は残らない
- PC-9821Ap3: AMARANTH の店頭デモが、直接起動したときと同じに表示される。このデモは、本体の CPU の速度の設定を High に
  すると途中で止まることがあるが、VBM98 を通さずに直接起動しても同じように止まる
- PC-9801BX（486DX2、SCSI のディスクから起動した MS-DOS 6.2）: EMM386.EXE（`/DPMI`）の下でも、EMM ドライバを入れない
  リアルモード（HIMEM.SYS などの XMS ドライバだけ）でも動く。2DD のディスク版 N88-BASIC(86) がファイル選択から起動する。
  テキストのスクリーンショットが撮れる
- PC-9801RA2（386DX 16MHz）: LEMM の下でも、リアルモードでも動く。市販ゲームの体験版 2 本で、FM 音源の音が途切れずに
  鳴る（起動とディスク交換のときに、イメージ 1 枚を読み込む時間がかかる）。MIDI インタフェースボード（MPU-PC98II）
  からの MIDI の演奏も遅れずに鳴る。ホットキーで DOS に戻ったあとも、キー入力は正常。400 ラインの画面、外字を使った
  テキスト画面、640×200 の 15kHz のモードの画面のスクリーンショットが撮れる。EMM386.EXE に `/HIGHSCAN` を付けて
  BASIC ROM の領域にも UMB を作った構成でも、ディスク版の N88-BASIC（2DD と 2HD）が起動する。SCSI の HDD から起動した
  ホストで、FreeDOS(98) の起動ディスクがゲストとして起動する
- PC-9821Na12（Pentium のノート型。MS-DOS 6.2、EMM386.EXE に `/UMB /HIGHSCAN /DPMI`、ドライバを `DEVICEHIGH` で
  読み込む構成）: 市販ゲーム 1 本が正常に動く。別の市販ゲーム 1 本は画面が黒いままだが、同じ機種で実物のフロッピーから
  直接起動しても動かないので、VBM98 の問題ではない
- PC-486NAS: DPS（アリスフリー宣言で配布されている D88）が動き、音も鳴る。GDC クロックが 2.5MHz の設定のホストで、
  DPS を終了したあとに別のソフトを起動しても、表示は崩れない。スクリーンショットは CTRL + GRPH + COPY で撮れる
- EPSON PC-586MV（Pentium、128MB、PC-9801-100 ボード）と PC-9821V166（MMX Pentium、96MB、同じボード）: 同じ SCSI の
  HDD から起動したホストで動く。80 桁 × 20 行のテキストモード（EPSON 機の N88-BASIC(86) 3.0。MS-DOS なら CTRL + f・6 で
  同じ状態）でも、VM メニューと、閉じたあとの画面の文字は崩れない
- ディスクイメージの D88（配布されているフリーのソフト）と HDB（BKDSK で作った N88-BASIC の 2HD）が起動する
- DPS の画面のテキストのスクリーンショットが撮れる（PC-9821Cr13。半角カナも写る）

実機で分かっている未解決の問題:

- PC-9821Cr13 で、まれに N88-BASIC のテキストが表示されない（カーソルだけ見える）。EMM ドライバの下で、起動直後に
  固まることがある
- Windows 98 の DOS に 30 行 BIOS を常駐させたホストでは、元の BIOS の入口が見つからず、ゲストでキーが連打された状態に
  なる（下の「うまく動かないとき」）
- PC-486NAS では、CTRL + GRPH + HELP を本体の BIOS が先に受け取って BIOS のメニューに入ってしまい、ゲストの実行中に
  VM メニューを開けない。そのため、ディスクを交換できない
- PC-9821Cr13 で、2DD のディスク版 N88-BASIC をファイル選択から起動すると、画面が黒いままだった（直しを入れたが、
  実機では未確認）
- PC-9821Na12 で、ディスク版の BASIC が起動しなかった（直しを入れたが、実機では未確認）

エミュレータ上で確認している範囲:

- 合成イメージによる自動試験（ディスクイメージ層、INT 1Bh の意味論、モニタ核、起動、スクリーンショット、VM メニュー）。
  ホストの DOS は FreeDOS(98)、DOSBox-X の内蔵 DOS、NEC の MS-DOS 5.0A と 6.2（HIMEM.SYS だけの構成。6.2 は、
  EMM386.EXE に `/UMB /HIGHSCAN /DPMI` を付けて UMB に常駐物を入れた構成でも）
- NFDMAKE（T98-Next のツール）で作った NFD r1 形式の MS-DOS 5.0A 起動ディスクから、MS-DOS が起動してディスクに書き込める
- FreeDOS(98) の起動ディスク（2HD と 1.44MB の生イメージ）から、FreeDOS(98) が起動してディスクに書き込める
- 市販ゲームのイメージ 3 本（NFD 形式。NP21/W で）。ソーサリアン、イース1、イース2 とも、キー操作ができる。
  ソーサリアンとイース2 は、ゲームが求めるディスクの入れ替えをしたあとも先へ進む。イース1 はタイトルから
  ゲーム本編に入る

まだ動かないもの:

- V30 エミュレーションのうち、ホストの CPU が例外にせずに実行してしまう並び（Pentium 以降の RDTSC、SSE として
  実行される 0F 1x / 28 / 2A など）と、REPC / REPNC、BRKEM
- 機種判別フラグの PC-9801VM 化（ホストの値のまま）
- EPSON 機で、NEC の MS-DOS や N88-BASIC(86) の機種チェックを通すこと（ROM は実物のまま見せるので、実物と同じく
  リセットを繰り返す）
- サウンド BIOS の割り込み（INT D2h）の登録（`-sbrom` は ROM を見せるだけ）
- DMA を使うソフト（DMA で PCM を鳴らす音源など）。ゲストの DMA の設定は仮想の DMA コントローラが受けるだけで、
  転送は起きない（転送の代行は対応予定）。`-log` を付けると、ゲストが DMA を使おうとしたことがログに残る

## 動作環境

- 80386 以上の CPU を搭載した PC-98x1。ノーマルモードで動いていること（ハイレゾモードは対象外）。
  EPSON の互換機も対象に含める（実物では未確認）
- MS-DOS。リアルモードで起動しているか、VCPI のある EMM ドライバの下で起動していること。
  FreeDOS(98) の EMM386 では動作を確認。NEC の MS-DOS 付属の EMM386.EXE は、そのままでは VCPI を提供しないので、
  「VCPI がない」と表示して止まる。MS-DOS 6.2 の EMM386.EXE は、`/DPMI` を付けると VCPI を提供する
  （例: `DEVICE=A:\DOS\EMM386.EXE /UMB /HIGHSCAN /DPMI`）。MS-DOS 5.0A の EMM386.EXE は `/DPMI` を付けても
  提供しないので、EMM386.EXE を外して起動する
- XMS ドライバ（HIMEM.SYS など）。ゲストのメモリを XMS から確保する
- メモリ: 空きコンベンショナルメモリ 256KB 以上と、XMS で確保できる拡張メモリ 700KB 以上。
  メインメモリ 640KB に拡張メモリ 1MB を足した標準的な構成（計 1.6MB）で足りる。
  内訳は本体と作業領域で約 220KB、ゲストの 640KB 分と画面の控え 24KB を XMS から確保する（コードから数えた値で、
  実機では未確認）
- 拡張メモリにさらに空きがあれば、ドライブに入れたディスクイメージを丸ごとメモリに読み込み、ゲストがディスクを
  読むときにホストのディスクにアクセスしない（ディスクを読む間の音の途切れを減らすため）。要るのは 1 枚につき
  イメージファイルの大きさぶん（2HD で 1.2MB から 1.4MB）。空きが足りないドライブは、ホストのファイルから必要なセクタだけを
  読む。切り替えは自動で、どちらになったかは起動時に表示する

## 使い方

```
VBM98 [@<プロファイル>] [-fdd0 <ファイル>[,<番号>]] [-fdd1 <ファイル>[,<番号>]] [-v30 on|off] [-dipsw <16進6桁>] [-memsw <16進16桁>] [-ss <名前>]
      [-sbrom <ファイル>[,C8|CC]] [-iotrap <ゲスト>=<ホスト>[,...] | -iotrap <ファイル>]
```

| オプション | 内容 | 省略時 |
| --- | --- | --- |
| `-fdd0 <ファイル>[,<番号>]` | ドライブ 0 にイメージを入れる。起動はこのドライブから。番号は、複数ディスク入りの D88 のうちどのディスクか（1 から） | 起動前にファイル選択を開く。取り消したら終了する。番号を省くと 1 枚目 |
| `-fdd1 <ファイル>[,<番号>]` | ドライブ 1 にイメージを入れる。番号は同上 | 空（ディスクなし） |
| `-v30 on` / `-v30 off` | V30 固有の命令（TEST1 / CLR1 / SET1 / NOT1、ADD4S / SUB4S / CMP4S、ROL4 / ROR4、INS / EXT）の代行と、ゼロ除算の戻り番地を V30 に合わせることの有効・無効 | `on` |
| `-dipsw <16進6桁>` | DIP スイッチ SW1・SW2・SW3 の値を、この順に 2 桁ずつ。各バイトは bit 0 が 1 番のスイッチで、1 が OFF（NP21/W の設定ファイルと同じ）。`*` の桁はホストの同じ桁の値を映す。ゲストにだけ作用し、ホストの DIP スイッチは変えない | ホストの現在値で、SW2-8 だけ OFF（GDC 2.5MHz）。ホストの値どおりにするには `-dipsw ******` |
| `-memsw <16進16桁>` | メモリスイッチ 8 個の値を、1 番から順に 2 桁ずつ。`*` の桁はホストの同じ桁の値を映す。ゲストにだけ作用し、ホストのメモリスイッチは変えない | ホストの現在値 |
| `-ss <名前>` | スクリーンショットのファイル名の先頭（4 文字まで。英小文字は大文字にする） | ドライブ 0 に最初に入れたイメージのファイル名の先頭 4 文字 |
| `-sbrom <ファイル>[,C8\|CC]` | サウンド BIOS の ROM イメージ（16KB が普通。32KB まで）をゲストに見せる。置く番地は `C8`（C8000h）か `CC`（CC000h）。ROM を見せるだけで、INT D2h の登録はしない | なし（ホストの実物）。番地を省くと CC |
| `-iotrap <ゲスト>=<ホスト>[,...]` | ゲストの I/O ポート番号をホストのポート番号に読み替える。番号は 16 進 1〜4 桁、コンマで複数（64 個まで） | なし |
| `-iotrap <ファイル>` | 読み替えの定義ファイル。1 行に `<ゲスト> <ホスト>`（16 進、空白区切り）を並べたテキスト。空行は無視 | なし |
| `@<プロファイル>` | オプションの組み合わせを書いたテキストファイルを、この位置に書いたものとして読む。中身はコマンド行と同じ書き方で、空白・タブ・改行で区切る。項目の頭の `#` から行末まではコメント。1,023 バイト・32 項目まで。同じオプションは、コマンド行とプロファイルを通して、後に書いたものが有効 | なし |
| `-log <ファイル>[,<秒>]` | 診断ログをファイルに書く（下の「うまく動かないとき」） | なし |

- オプション名と値の大文字・小文字は区別しない。同じオプションを繰り返したら後のものが有効
- イメージが開けないときはメッセージを出して終了する
- 起動するときとリセットするときに、テキスト画面とグラフィック画面を消す（前に動かしていたソフトの絵は残らない）
- 起動時に、ドライブごとに、イメージをメモリに読み込むか（`reading the image into memory`）、ファイルから読むか
  （`read from the file as needed`）を表示する。メモリに読み込む間は、イメージ 1 枚ぶんの読み込み時間だけ待つ
  （ディスク交換のときも同じ）
- 起動時にホストのメモリスイッチの値（8 バイト）と、DIP スイッチの読み出しポート 3 つの値を表示する。
  `-memsw` と `-dipsw` の値はそれを元に組む（ポート 31h の値がそのまま SW2。SW1 と SW3 は一部のビットしか読めない）
- `-dipsw` を省略すると、ホストの DIP スイッチがそのまま見えるが、SW2-8（グラフィック GDC のクロック）だけは OFF
  （2.5MHz）に見せる。古いソフトは 2.5MHz を前提にしていて、5MHz の設定のままだと表示が崩れることがあるため。
  ホストの設定は変えない。ホストの値どおりに見せたいときは `-dipsw ******`
- `-dipsw` の `*` で映せるのは、ホストのポートから読める SW2 の全部と SW1-1・SW1-3・SW1-8・SW3-8。
  他のビットは ON（0）になる

```
VBM98 -fdd0 GAME.NFD
VBM98 -fdd0 DISK1.FDI -fdd1 DISK2.FDI -ss GAME
VBM98 -fdd0 GAME.D88,2
VBM98 -fdd0 GAME.NFD -memsw ******08********
VBM98 -fdd0 GAME.NFD -sbrom SOUND.ROM -iotrap 188=288,18A=28A
VBM98 @GAME.PRO
```

`GAME.PRO` の中身の例（コマンド行が 126 文字に収まらないときや、同じ組み合わせを何度も使うときに）:

```
# GAME 用の設定
-fdd0 GAME.NFD -fdd1 USER.HDM
-memsw ******08********
-sbrom SOUND.ROM -iotrap 188=288,18A=28A
```

3 つ目は、メモリスイッチ 4 だけを 08h にし、他はホストの値のままにする例。4 つ目は、サウンド BIOS の ROM イメージを
CC000h に見せ、ゲストが 188h / 18Ah を叩いたらホストの 288h / 28Ah に通す例。

### ホットキー

ゲストの実行中に効く。

| キー | 動作 |
| --- | --- |
| CTRL + GRPH + HELP | VM メニュー（仮想マシンのメニュー）を開く。下の 5 つを選べる |
| CTRL + GRPH + テンキーの 0 | ドライブ 0 の取り出し・入れ替え（イメージファイルの選択） |
| CTRL + GRPH + テンキーの 1 | ドライブ 1 の取り出し・入れ替え（イメージファイルの選択） |
| CTRL + GRPH + COPY | スクリーンショットの保存 |
| CTRL + GRPH + DEL | リセット（イメージから再起動。実機のリセットと同じ組み合わせで、問い合わせはない） |
| CTRL + GRPH + STOP | 仮想マシンの終了（問い合わせの後） |

- VM メニューの項目は、ディスク交換（ドライブ 0・1）、スクリーンショットの保存、終了、リセット。終了とリセットは  問い合わせの後
- メニューとファイル選択のあいだゲストは一時停止し、テキスト画面は退避してから復元する。グラフィック表示は
  消しておき（VRAM は変えない）、閉じるときにゲストの設定していた状態に戻す
- メニューとファイル選択は、ゲストのテキスト画面が 20 行や 40 桁でも 25 行・80 桁で出し、閉じるときにゲストの
  行数・桁数へ戻す
- ファイル選択の一覧には .fdi .nfd .fdd .hdm .img .d88 .hdb を出す。全ファイルの表示に切り替えられる
- 複数ディスク入りの D88 を選ぶと、続けてそのファイルのディスクの一覧（ディスク名）から 1 枚を選ぶ
- ファイル選択で N を押すと、ブランクディスク（ユーザーディスク用の空のイメージ）を作ってそのドライブに入れる。大きさを
  2HD 1.25MB / 2DD 640KB / 1.44MB から選び、ファイル名を入れる（拡張子を省くと .HDM）。中身は全セクタを E5h で埋めた
  だけで、MS-DOS などの論理フォーマットはしていない（ゲームが自分で初期化する前提）
- ゲストが割り込み禁止のまま HLT で止まったとき（アプリが自分で終了したとき）も VM メニューが開く
- 終了すると MS-DOS のプロンプトに戻る

**VMメニュー表示中は、ゲストCPUが一時停止状態になるので、その時音が鳴っている場合はずっと鳴りっぱなしになる**

### スクリーンショット

表示中のグラフィック画面とテキスト画面を別々の PNG にして、ホストのカレントディレクトリへ保存する。
ファイル名は `<名前>###G.PNG`（グラフィック）と `<名前>###T.PNG`（テキスト）。`<名前>` は `-ss` の値、
`###` は 001 から 999 で空いている最小の番号。

- グラフィックは 640×400（200 ラインの画面は縦 2 倍）。8 色モードならデジタルパレットの 8 色、
  16 色モードならアナログパレットの 16 色
- テキストは 640×400 で、文字のない画素を透明にする。行の間隔は画面と同じ（25 行の画面は 1 行 16 ライン、20 行の
  画面は 1 行 20 ラインで 20 行。200 ラインの画面は縦 2 倍）
- 1 バイト文字の形は、起動時に読んでおく。そのため、起動時に画面が一瞬消える
- ホットキーで撮るとき、ゲストがグラフィックチャージャーを使って描いている最中で画面が読めなければ、描き終わるのを
  待ってから撮る。VM メニューから撮るときは待てないので、そのまま撮ると 2 色の模様のような絵になることがある。
  その場合はメニューを閉じて、ホットキーで撮り直す

### 対応ディスクイメージ

| 形式 | 由来 | 拡張子の例 |
| --- | --- | --- |
| FDI | Anex86 | .fdi |
| NFD r0 / r1 | T98-Next | .nfd |
| FDD | Virtual98 | .fdd |
| RAW（ヘッダなし） | SL9821 など | .hdm ほか |
| D88 | PC-88 / PC-98 系のエミュレータ全般 | .d88 ほか |
| HDB（ヘッダなし。N88-BASIC の 2HD） | BKDSK | .hdb |

形式は拡張子ではなくファイルの中身で判定する。RAW として受け付けるサイズは 1.25MB / 1.21MB / 1.44MB /
720KB / 640KB の 5 種。HDB は 1,021,696 バイト（トラック 0 の表だけ単密 128 バイト × 26、ほかは倍密 256 バイト × 26）の
もの。複数ディスク入りの D88 は、`-fdd0` / `-fdd1` の番号かメニューの一覧で 1 枚を選ぶ。書き込みは BIOS 呼び出しのたびに
イメージファイルへ反映する（イメージをメモリに読み込んでいるときも同じ）。

### 対象外

- FDC を BIOS を通さず直接操作するアプリ

### うまく動かないとき

VBM98 が DOS に戻ったときは、戻った理由（`VBM98: exit ...`、`VBM98: guest raised an unexpected exception ...` など）を
画面に表示します。

`-log` を付けて起動すると、画面がゲストに取られていても、本体の表示（起動時のホストの設定、INT 1Bh の呼び出し、
リセット、止まったときのレジスタと直近のイベント）がファイルに残ります。

```
VBM98 -fdd0 GAME.NFD -log VBM98.LOG,2
```

`,2` のように秒を付けると、その間隔でゲストの位置（CS:IP）と割り込みの回数、直近のイベントを書き足します。
固まってしまう場合も、最後に書かれた心拍までの様子が残ります。ログは 1 行ごとに DOS に書き戻しているので、
リセットしてもファイルは読めます（追記なので、不要になったら消してください）。

- 秒を付けている間は、ゲストが設定したタイマ割り込みの周期を、約 10ms に上書きします。タイマを使うソフトの動きが変わることが
  あるので、固まる場所を調べるときだけ付けてください。ふだんは秒なしの `-log VBM98.LOG` で足ります
- 起動時に `VBM98: warning: INT 18h is hooked in the host ...` と表示されたときは、ホストの常駐物がキーボードと画面の
  BIOS（INT 18h）を横取りしていて、VBM98 が元の BIOS の入口を見つけられなかった状態です。そのまま起動しても、ゲストで
  キー入力が効きません。その常駐物（キー入力を拡張するものなど）を外して起動してください。30 行 BIOS と AutoMATE は
  入口を見つけられます（Windows 98 の DOS に 30 行 BIOS を常駐させた構成では、まだ見つけられません）。
  ほかの番号で同じ警告が出たときも、その割り込みはゲストで働きません
- 画面が黒いまま固まるなど、何も手がかりが残らないときは、`-progress` を付けて起動してください。画面の右上に
  `E0001 X0003 Ph I0 K0` の形で進み具合を表示し続けます（E はゲストへ入った回数、X は最後に戻った理由、P は VBM98 側の
  どの処理の中か、I と K はゲストの実行中に来た割り込みとキーボード割り込みで変わる 1 桁）。固まった画面の右上が
  写った写真を Issues に貼っていただけると、どこで止まったかが分かります。表示のためにテキスト画面を ON にするので、
  ゲストの画面に文字が重なります
- 起動の途中などで、操作していないのに VM メニューが開いたときは、ゲストが割り込みを禁止したまま止まっています
  （ソフトが自分で止まったか、動作がおかしくなって止まった状態）。メニューの「スクリーンショットの保存」を選ぶと、
  止まったときにゲストが表示していた画面を保存できます。`-log` を付けていれば、止まった番地、レジスタ、直前に
  呼ばれた割り込みがログに残ります。この 2 つを Issues に貼っていただけると原因を調べられます
- ゲストの例外などで止まったときは、その内容（例外の番号と番地、レジスタ、割り込みの状態、直近のイベント）を画面に
  表示して、キーが押されるのを待ちます。その画面の写真を Issues に貼っていただけると原因を調べられます。キーを押すと
  DOS に戻り、同じ内容をもう一度表示します（ログにも残ります）。出力をファイルに向けているときは待ちません

## 実機での動作報告のお願い

実機での確認が足りていないので、動いた・動かなかったどちらの報告も助かります。[Issues](https://github.com/madscient/VirtualBareMetal98/issues)
に、次の情報を添えて書いてください。ディスクイメージそのものは送らないでください（市販ソフトの複製になります）。

| 項目 | 書いてほしいこと |
| --- | --- |
| VBM98 の版 | 起動時に出る `VBM98 x.y.z` の行（ログの先頭にも出ます）。自分でビルドした場合はコミットの ID |
| 機種 | 型番（例: PC-9801RA21、PC-9821Ap2）、CPU とクロック（CPU アクセラレータがあればそれも）、メモリの量（メインと拡張）、EPSON 機ならその型番 |
| 増設ボード | サウンドボードの種類と設定（PC-9801-26K / 86 など、I/O アドレス、サウンド BIOS の有無）、SCSI / IDE、その他の C バス機器 |
| DIP スイッチ・メモリスイッチ | 起動時に VBM98 が表示する `host memsw 1-8:` と `host dipsw ports 31h 33h 42h:` の行（ログに入ります） |
| DOS | 種類と版（MS-DOS 3.3D / 5.0A-H / 6.2、FreeDOS(98) など） |
| CONFIG.SYS と AUTOEXEC.BAT | 全文。常駐物（HIMEM.SYS、EMM386、ディスクキャッシュ、FEP、常駐ユーティリティ）がそのまま分かるように |
| 実行したコマンド行 | `VBM98 -fdd0 ... -log ...` のとおりに |
| 対象ソフト | タイトルと発売元、ディスクの種類（2HD / 2DD、何枚組）、イメージの形式（FDI / NFD / FDD / RAW）と作ったツール、イメージを他のエミュレータ（NP21/W など）で起動できるか |
| 何が起きたか | どこまで進んだか（タイトル、メニュー、ゲーム本編）と、止まり方（何も表示されない、画面が乱れる、音が鳴り続ける、固まる、DOS に戻る、メッセージが出る）。できれば再現する手順 |
| ログ | `-log <ファイル>,2` を付けて起動したときのファイル。固まった場合もそのファイルを |
| スクリーンショット | 可能なら CTRL + GRPH + COPY で保存した PNG、または画面の写真 |

動いた場合も、機種・DOS・対象ソフト・VBM98 の版の 4 つだけで十分です。

## ビルドと試験

ビルドは Linux 上の gcc-ia16（`ia16-elf-gcc` と libi86）で行う。Windows では WSL を使う。
道具の入れ方と試験の実行環境の指定は [docs/setup.md](docs/setup.md)。

| コマンド | 内容 | 要るもの |
| --- | --- | --- |
| `sh tools/build16.sh` | DOS 向けのビルド。`build/dos/VBM98.EXE` ができる | gcc-ia16、Python 3 |
| `python tests/run_host_tests.py` | ディスクイメージ層と INT 1Bh の意味論をホスト OS 上で試験する | gcc、Python 3 |
| `python tests/run_dos_tests.py` | 16 ビット版のディスクイメージ層、モニタ核、起動、スクリーンショット、VM メニューを DOS 上で試験する | 上のビルド結果、DOSBox-X か NP21/W |

試験は仕様書から自作した合成イメージで行う。実物のディスクイメージはリポジトリに入れない。
