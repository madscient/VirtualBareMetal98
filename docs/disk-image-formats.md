## 共通

- 多バイトの値はリトルエンディアン。構造体は 1 バイト境界
- セクタ長は `128 << N` バイト
- トラック番号は `シリンダ × 2 + ヘッド`
- 判定は中身で行い、拡張子は見ない。順序は NFD（識別子）→ FDD（識別子）→ FDI（ヘッダとサイズの整合）→ RAW（サイズ）

## RAW

ヘッダなし。シリンダ 0・ヘッド 0・セクタ 1 から順にセクタの中身が並ぶ。ファイルサイズだけで構造を決める。

| サイズ | シリンダ | セクタ/トラック | N | 媒体 |
| ---: | ---: | ---: | ---: | --- |
| 1,261,568 | 77 | 8 | 3 | 2HD 1.25MB |
| 1,228,800 | 80 | 15 | 2 | 2HD 1.21MB |
| 1,474,560 | 80 | 18 | 2 | 1.44MB |
| 737,280 | 80 | 9 | 2 | 2DD 720KB |
| 655,360 | 80 | 8 | 2 | 2DD 640KB |

いずれも両面。この表にないサイズは開かない。

## FDI

4096 バイトのヘッダ（先頭 32 バイトだけが意味を持つ）の後ろに、RAW と同じ並びのデータが続く。

| 位置 | 項目 | 内容 |
| ---: | --- | --- |
| +0 | dummy | 0 |
| +4 | fddtype | 媒体種別。上位ニブルで判定する |
| +8 | headersize | ヘッダ長（通常 4096）。データはここから始まる |
| +12 | fddsize | データ部の長さ |
| +16 | sectorsize | セクタ長（バイト） |
| +20 | sectors | セクタ/トラック |
| +24 | surfaces | 面数 |
| +28 | cylinders | シリンダ数 |

fddtype の上位ニブル: `1` `7` `F` = 2DD、`3` `B` = 1.44MB、`5` `D` = 2D、`9` = 2HD。

識別子がないので、次をすべて満たすものを FDI と見なす。

- sectorsize が 128〜16384 の 2 のべき乗、sectors が 1〜255、surfaces が 1〜2、cylinders が 1〜127
- headersize が 32 以上で、`headersize + sectorsize × sectors × surfaces × cylinders` がファイルサイズに等しい
- fddtype の上位ニブルが上の一覧にある

## NFD r0

| 位置 | 項目 | 内容 |
| ---: | --- | --- |
| +0x000 | szFileID[15] | `T98FDDIMAGE.R0` と終端の 0 |
| +0x010 | szComment[0x100] | コメント |
| +0x110 | dwHeadSize | ヘッダ長。データ部はここから始まる |
| +0x114 | flProtect | 0 以外で書き込み禁止 |
| +0x115 | byHead | ヘッド数 |
| +0x120 | si[163][26] | セクタ ID。1 要素 16 バイト、トラック番号順 |
| +0x10A00 | Reserve3[0x10] | 予備 |

セクタ ID（16 バイト）: `C H R N flMFM flDDAM byStatus byST0 byST1 byST2 byPDA` と予備 5 バイト。

- C が 0xFF の要素は未使用
- byStatus は収録時に INT 1Bh の READ DATA が返した結果、byST0〜2 はそのときの FDC のリザルト
- byPDA は媒体のデバイス種別: 0x90 = 1.2MB、0x30 = 1.44MB、0x10 = 640KB
- データ部には、未使用でない要素の中身が、表の並び順のまま隙間なく並ぶ

## NFD r1

先頭の全体情報部（0x3C0 バイト）の後ろに、トラックごとの情報が続く。

| 位置 | 項目 | 内容 |
| ---: | --- | --- |
| +0x000 | szFileID | `T98FDDIMAGE.R1` と終端の 0 |
| +0x010 | szComment[0x100] | コメント |
| +0x110 | dwHeadSize | ヘッダ部全体の長さ。データ部はここから始まる |
| +0x114 | flProtect | 0 以外で書き込み禁止 |
| +0x115 | byHead | ヘッド数 1〜2 |
| +0x120 | dwTrackHead[164] | 各トラックの情報の位置（ファイル先頭から）。存在しないトラックは 0 |
| +0x3B0 | dwAddInfo | 予約（0） |

トラックの情報は、トラック ID（16 バイト: `wSector`, `wDiag`, 予備）、`wSector` 個のセクタ ID、`wDiag` 個の特殊読み込み ID の順。

- セクタ ID（16 バイト）: `C H R N flMFM flDDAM byStatus bySTS0 bySTS1 bySTS2 byRetry byPDA` と予備 4 バイト
- 特殊読み込み ID（16 バイト）: `Cmd C H R N byStatus bySTS0 bySTS1 bySTS2 byRetry dwDataLen byPDA` と予備 1 バイト
- byRetry は不安定なデータを複数通り持つときの追加の通り数。データは `1 + byRetry` 通りが連続して入る
- Cmd は特殊読み込みの対象コマンド（INT 1Bh の AH の下位 4 ビット。READ DATA = 06h、READ DIAGNOSTIC = 02h）
- byPDA は r0 と同じ。0 のときは読む側がセクタ長から媒体を判別する、と資料にある
- データ部には、トラック番号順に、各トラックのセクタのデータ（`128 << N` × 通り数）、続いて特殊読み込みのデータ（`dwDataLen` × 通り数）が隙間なく並ぶ

### NFDMAKE が作る NFD r1

NFDMAKE を走らせて、INT 1Bh の呼び出しと出来たイメージを見た結果（確度は下の「確認済み」）。

- オプションは `-r0`、`-r1`（既定）、`-r1s`（解析を一部省く）、`-r1d`（詳細）。`-r1` でも特殊読み込みのデータが入るので、
  1 枚が 3MB を越える。大きさだけでは `-r1` と `-r1d` を見分けられない
- セクタ ID は READ ID の繰り返しで集める（まず倍密と単密を交互に試し、最初の ID がもう一度返ったところで集め終える）。
  並びは最初に READ ID が返した ID から始まり、R = 1 が先頭とは限らない。ID の C・H・R・N は READ ID が返した値のまま
- 各セクタは READ DATA（その ID の C・H・R・N、1 セクタぶんの長さ）で読み、結果を byStatus と bySTS0〜2 に入れる
- 特殊読み込みは READ DIAGNOSTIC（Cmd = 02h）だけ。C・H・R は最初のセクタ ID のもの、N を変えて 1 個ずつで、長さは
  `128 << N`。`-r1d` は N = 0 から 6 まで全部（実際の N も含む）。`-r1` は、N = 3 のディスクで N = 4〜6 の 3 個だった
  （ほかの N のディスクでは見ていない）。BIOS が受け付けなかった組み合わせは byStatus が D0h のまま入る（NP21/W の
  BIOS では、倍密のトラックの N = 0 と、単密のトラックの N ≥ 3）
- トラックの情報とデータは番号順に並ぶ。データ部の終わりはファイルの終わりに一致する

## FDD（Virtual98）

0xC3FC バイト固定のヘッダの後ろにセクタのデータが置かれる。データの位置は位置表が指すので、並び順は自由。

| 位置 | 項目 | 内容 |
| ---: | --- | --- |
| +0x00 | verID[8] | `VFD1.00` と終端の 0 |
| +0x08 | memo[128] | コメント |
| +0x88 | write_protect (WORD) | 0 以外で書き込み禁止 |
| +0x8A | spdrv (WORD) | 特殊読み込みドライブ。0xFFFF = なし |
| +0x8C | 予約 80 バイト | 0 |
| +0xDC | 位置表 [160][26] | 1 要素 12 バイト、トラック番号順 |
| +0xC3DC | 特殊読み込みデータ 32 バイト | |

位置表の要素（12 バイト）: `C H R N D DDAM flMF flHD dataPoint(DWORD)`。

- C が 0xFF の要素は未使用
- dataPoint はセクタのデータの位置（ファイル先頭から）。0xFFFFFFFF のときはファイルにデータがなく、セクタ全体が D の値で埋まっているものとして扱う
- flMF は倍密度、flHD は 2HD

## 確度

### 確認済み

この文書どおりに作った合成イメージを `dimg.c` が期待どおりに読み書きすること。

- 方法: `python tests/run_host_tests.py`（開けるもの 28 件、開けてはいけないもの 11 件）
- 試験が誤りを捕まえること: `dimg.c` に 17 通りの誤り（データ位置の計算、要素の大きさ、フラグの取りこぼし、書き込み禁止の無視など）を 1 つずつ入れ、いずれでも試験が落ちることを確かめた

**範囲の限定**: 書き手（[tools/mkimg.py](../tools/mkimg.py)）と読み手を同じ解釈で作っている。これは解釈の内部整合の確認であって、各エミュレータが出力した実物を読める、という確認ではない。

NFD r1 だけは、実物の道具の出力でも確かめた。

- 方法: 中身が分かっている合成ディスク 2 種（1024 バイト × 8 セクタの 2HD、トラック 0 の表だけ単密 128 バイト × 26・ほかは
  倍密 256 バイト × 26 の 2HD）を、PC-98 エミュレータ（NP21/W）上の MS-DOS 5.00A で NFDMAKE に吸い出させた（`-r1` と `-r1d`、
  計 3 本）。`dimg.c` の読み取り（全セクタと全特殊読み込みの ID・ステータス・データの CRC）が、別に書いた読み取りと 1 件も
  違わず、全セクタのデータが元のディスクの内容に一致した
- 起動まで: MS-DOS 5.00A の起動ディスク（1024 バイト × 8 セクタの 2HD）を同じ手順で `-r1` と `-r1d` の NFD にし、VBM98 の
  ドライブに入れると、MS-DOS がゲストとして起動し、AUTOEXEC.BAT が NFD の中にファイルを書いた（DOSBox-X と NP21/W。
  書かれたファイルは、実行後の NFD を別に読んで確かめた）。吸い出す元は D88 にしたもの（ID が正しく記録される）。
  生イメージのまま吸い出した NFD は、下の表の「ID の C がシリンダ番号と違う」に当たり、起動しない
- **範囲の限定**: 吸い出しはエミュレータの FDC と BIOS を通している。ステータスの値と ID の一部はエミュレータの応答で、
  実機の FDC が返すものとは違いうる（下の表の「ID の C がシリンダ番号と違う」）。実機で吸い出した NFD、複数通りのデータ
  （byRetry）を持つ NFD、NFD r0 は未確認

### 未検証

各エミュレータやツールが実際に出力したファイルの読み書き。実物のイメージで確かめる。

### 解釈が分かれる点

資料から一意に決まらず、こちらで選んだもの。実物のイメージで食い違いが出たら見直す。

| 点 | 本実装の扱い | 根拠・留保 |
| --- | --- | --- |
| NFD r1 のデータの並び | トラック番号順 | 資料は「ヘッダに格納された順」。トラック情報がファイル内で番号順に置かれていない場合の扱いは未確認。参考実装は番号順 |
| NFD で byPDA が 0 | 2HD と見なす | 資料は「セクタサイズから自動判別」。判別の規則は未入手。参考実装も 1.2MB 扱い |
| NFD で byPDA が 0x90 / 0x30 / 0x10 以外 | 2HD と見なす | 参考実装は r0 では開かない |
| NFD r0 の dwHeadSize が位置表の終わりより小さい | 開かない | 参考実装のコメントに、期待した値が入っていないファイルがあるとの記述がある。どんな値なのかは未確認 |
| NFD で byHead が 1 | トラック番号の式は両面と同じ | 資料に記述なし |
| NFD のセクタ ID の C がシリンダ番号と違う | ID の値をそのまま持ち、読み込みでは C も照合する（design.md §8）。ゲストがシリンダ番号で読むと D0h になる | 確認済み（NP21/W）: 平坦な形式（RAW・FDI など）のイメージを NP21/W 上の NFDMAKE で吸い出すと、各トラックの R = 1 の ID だけ C が 1 多くなる（参考実装の READ ID が最終セクタの次でトラック番号を進めるため）。そういう NFD は VBM98 では起動時に `cannot read the IPL (status D0)` になる。参考実装は読み込みで R しか見ないので読める |
| FDD の位置表の引き方 | 表の中の位置（トラック番号 × 26）で引き、要素の C / H は ID として返す | 参考実装は、データ位置だけを要素の C / H から引いている。両者が一致するイメージでは差が出ない |
| FDD で dataPoint が 0 | データなしと見なす | 資料は 0xFFFFFFFF のみ。参考実装は 0 も同じ扱い |
| FDD の媒体種別 | 先頭トラックの最初の要素の flHD が 0 なら 2DD。0 以外で、N = 2 かつ 18 セクタ以上なら 1.44MB、それ以外は 2HD | 形式に媒体種別の項目がない。参考実装の推定をなぞった |
| FDD の識別子 | 先頭 5 文字 `VFD1.` で判定 | Virtual98 は先頭 3 文字しか見ない、`VFD1.01` のファイルが存在する、と資料にある |
| FDD の特殊読み込みデータ | 無視する | Virtual98 自身が使っていない、と資料にある |
| RAW の 655,360 バイト | 512 バイト × 8 セクタと見なす | 256 バイト × 16 セクタの 2DD と同じサイズ。中身では区別できない |
| FDI で surfaces が 1 | 受け付ける | 参考実装は 2 だけを受け付ける |
