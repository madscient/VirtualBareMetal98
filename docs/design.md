# 設計

読者: 開発者・AI。方式と、その決定の理由・前提を書く。要件は [spec.md](spec.md)。

動かして確かめてあるのは、ディスクイメージ層（§8 の最下層）と、モニタ核のうち機種に依らない
部分（モード切替、例外の入口、割り込みの反射、ページの差し替え）である。それ以外は設計だけで、
ハードウェアや CPU の振る舞いについての記述の確度は §12 にまとめてある。

## 1. 全体像

```
        ホスト世界                       モニタ                     ゲスト世界
   ┌───────────────────┐         ┌───────────────┐         ┌─────────────────────┐
   │ MS-DOS (リアルモード) │ ◀─切替─▶ │ 保護モード ring 0 │ ◀─例外─▶ │ 仮想 PC-98 (仮想86モード) │
   │  ファイル入出力        │         │  割り込みの反射   │  割込み  │  ベアメタルアプリ       │
   │  FDD BIOS の意味論    │         │  BIOS の横取り    │         │  実機の ROM BIOS      │
   │  ディスク交換メニュー   │         │  ページング       │         │                     │
   └───────────────────┘         └───────────────┘         └─────────────────────┘
        本来の下位 640KB              両方の世界の外に常駐          拡張メモリ上の別の 640KB
```

ホストの MS-DOS とゲストのアプリは、どちらも「下位 1MB を丸ごと自分のもの」として動く。
同じ番地を二者が使うので、ゲストには拡張メモリ上に別の 640KB を与え、ページングでそれを
下位番地に見せる。ホストの MS-DOS は元の場所に手つかずで残るので、イメージファイルの
読み書きにも、終了後のプロンプト復帰にもそのまま使える。

同時に走るのは常に片方だけで、切り替えはモニタが行う。

## 2. 決定と前提

| # | 決定 | 理由 | 前提（崩れたら見直す） |
| --- | --- | --- | --- |
| D1 | ホスト世界は仮想86にせず、リアルモードに戻して走らせる | HIMEM やディスク BIOS、常駐物が特権操作や保護モードを使っても、何も仮想化せずに動く。モニタが面倒を見る対象がゲストだけになる | ホストがリアルモードで起動している。VCPI 対応時は「ホストへ移る／戻る」の 2 手続きだけを VCPI 経由の実装に差し替える |
| D2 | ゲストは IOPL=3 の仮想86で動かし、I/O ポートは原則素通しにする | ベアメタルアプリは割り込みの禁止・許可や I/O を多用する。それを毎回トラップすると遅い。ゲストは 1 つだけで CPU を分け合わないので、割り込みフラグを仮想化する必要がない | ゲストが 1 つ。ホストとゲストが同時に走らない |
| D3 | BIOS の横取りは、ROM のエントリ先頭 1 バイトを HLT に差し替えた「写しページ」で行う（§5） | INT 命令で呼んでも、ベクタを読んで far call しても、ゲストが自前のフックを挟んでも、最後に ROM へ入る瞬間に捕まえられる | ROM エントリの番地が分かる（§6）。分からない機種では INT 命令の時点で横取りする方式に落とす |
| D4 | FDD BIOS の意味論はホスト世界の C で実行し、モニタはゲストのメモリとの複写だけを受け持つ | 論理の大半を、同じソースのままホスト OS 上で検証できる | BIOS 呼び出し 1 回につき世界の切替 1 往復、という所要時間が許容できる（未計測） |
| D5 | セクタデータの受け渡しは、ホストの下位メモリに確保した 64KB の転送バッファを介す | リアルモードのホストからはゲストのメモリ（拡張メモリ上）に届かない。INT 1Bh の転送長は 16 ビットなので、64KB あれば 1 回の呼び出しを 1 往復で済ませられる | — |
| D6 | イメージの管理情報は常駐させず、トラック単位で読む | NFD r0 のヘッダは 68KB あり、near データに収まらない | ホストのファイルアクセスが十分速い（HDD 上のイメージを想定） |
| D8 | 例外・割り込みの判断は ring 0 で動く C で書き、アセンブリはモード切替と入口・出口だけにする | 判断の部分が読みやすく、試験を足しやすい。アセンブリの量が減る | 保護モードのコード・データセグメントを、実行ファイルのそれと同じ場所を指す 16 ビットセグメントにしてあること（§4）。割り込み 1 回あたりに C の関数呼び出しが挟まる時間が許容できること（未計測） |
| D7（検討中） | ゲスト世界でも線形の 0 番ページ（割り込みベクタと BIOS ワークエリアを含む 00000–00FFF）だけは物理の 0 番ページに写像し、世界を切り替えるたびに中身を入れ替える | BIOS を内蔵の実装で代行するエミュレータは、BIOS ワークエリアを物理番地で直接読み書きし、ページングを通らない。0 番ページを物理と一致させておけば、そうした環境でも実機でも同じに動く | 開発と試験にそうしたエミュレータを使うこと（§12）。実機だけを対象にするなら不要で、他のページと同じ扱いに戻せる。値段は世界の切替 1 回につき 4KB の複写 2 回 |

## 3. メモリとページング

ゲスト世界の線形アドレスの割り当て。

| 線形アドレス | 写像先 | 備考 |
| --- | --- | --- |
| 00000–9FFFF | ゲスト用に確保した拡張メモリ | 割り込みベクタと BIOS ワークエリアもここに入る |
| A0000–FFFFF | 同じ番地の実メモリ | VRAM と ROM は実物を共有する。横取り用に差し替えたページだけが RAM の写し |
| 100000–10FFFF | A20 の状態に応じて、00000–0FFFF と同じページ／何もなし | A20 を閉じた実機と同じ折り返しを再現する |
| モニタ用の高位アドレス | モニタのコード・データ・GDT・IDT・TSS・ページテーブル | ゲストの 1MB の外に置き、ゲストからは見えない |

- ゲスト用メモリは XMS（HIMEM.SYS）があればそこから確保して固定する。なければ BIOS の拡張メモリ量から直接切り出す。確保経路は差し替えられる形にする（VCPI 用の 3 つ目が来る）
- モニタは 16 ビットのコードセグメントで書き、必要な箇所だけ 32 ビットのオペランドを使う。実行ファイルを 16 ビットの DOS プログラム 1 本にまとめるため

## 4. 割り込み・例外・特権命令

- IDT の全ベクタを 32 ビットの割り込みゲート（DPL=3）にし、ベクタ番号を積んで共通処理へ入る
- 共通処理は原則として「ゲストの割り込みベクタ表を引いて、ゲストのスタックに FLAGS・CS・IP を積み、そこへ飛ばす」。ハードウェア割り込みもソフトウェア割り込みも同じ扱い
- PC-98 では IRQ のベクタ（08h–17h）が CPU 例外の番号と重なる。仮想86モードからの進入は必ず同じスタック位置から始まるので、エラーコードが積まれているか（＝スタックの深さ）で例外と割り込みを見分ける
- 一般保護例外で扱うもの: HLT（割り込み待ち、または §5 の横取り印）、トラップ指定した I/O ポート、それ以外は異常としてゲストを止めて報告する
- モニタ自身の実行中に例外が起きたら、状態を表示して MS-DOS に戻る

ring 0 で動く C には制約がある。守られないと保護モードで例外になるが、リアルモードでは
何も起きないので、ビルド時に検査する（`tools/build16.sh`）。

- 名前が `_r0.c` で終わるファイルに置き、保護モード向けの設定（`-mprotected-mode`）でコンパイルする。
  通常の設定で gcc-ia16 が出すコードは、セグメントレジスタを値の置き場として使う
- C ライブラリとコンパイラの補助関数（32 ビットのシフト・乗除算、構造体の複写が化ける `memcpy` など）を
  呼ばない。外部への参照は `mon_` で始まる名前だけにする
- far ポインタを使わない。ゲストのメモリは線形番地を指定する補助関数で読み書きする

C から呼ぶアセンブリの関数は、gcc-ia16 の規約に合わせて SI・DI・BP・ES を保存する
（ES は「呼ばれる側が保存するレジスタ」で、コンパイラが呼び出しをまたいで値を置く）。

トラップする I/O ポート（最小限）:

| ポート | 目的 |
| --- | --- |
| CPU リセット | 仮想マシンの再起動として扱う（§10） |
| A20 制御 | §3 の折り返しを切り替える |
| キーボードのデータ・ステータス | ポーズキーを見張る（§9） |
| テキスト表示まわりの書き込み専用レジスタ | 値を控えておき、メニューを閉じるときに戻す（§9） |

## 5. BIOS 呼び出しの横取り

ROM BIOS のエントリがあるページを RAM に写し、エントリ先頭の 1 バイトを HLT に書き換えて、
ゲスト世界ではその写しを見せる。ゲストがそこへ来ると一般保護例外になるので、番地が登録済みの
横取り印と一致すればモニタが処理する。処理後は、ゲストのスタックに積まれている割り込みフレームを
使って呼び出し元へ戻す。

横取りの対象:

| 対象 | 処理 |
| --- | --- |
| INT 1Bh（ディスク BIOS） | デバイス種別がフロッピーならイメージで応える（§8）。それ以外は §13 の方針による |
| リセットベクタ FFFF:0000 | 仮想マシンの再起動（§10） |
| INT 1Fh のうち保護モードを使う機能 | ゲストに拡張メモリを見せる場合に必要。初版は「拡張メモリなし」として機能ごと失敗を返す |

横取りの表は件数を固定せず、番地と処理の組を並べる形にする。

## 6. ゲストの初期状態

ゲストには「電源投入後、IPL に入る直前」の PC-98 を見せる必要がある。ところがホストは MS-DOS が
動いている状態で、割り込みベクタの一部は MS-DOS やドライバ（RAM 上のコード）を指している。
ゲストの 640KB にそのコードは存在しないので、そのままは渡せない。

割り込みベクタ（256 本とも同じ規則で決める）:

1. ホストのベクタが ROM 領域を指していれば、そのまま使う
2. RAM を指している場合、ROM のエントリを突き止められたらそれを使う。方法は、ホスト世界で
   その割り込みを無害な機能番号で 1 回呼び、シングルステップで追って最初に ROM へ入った番地を採る
3. 突き止められなければ、ROM 内の IRET 1 バイトを指す。それが IRQ のベクタなら、ゲストの
   割り込みマスクの初期値でその IRQ を閉じる

BIOS ワークエリア（0000:0400–05FF）はホストのものを写し、次を直す。

- ブートデバイス、ディスク装備情報（仮想ドライブの構成に合わせる。HDD は §13 の方針による）
- 拡張メモリ量（§13 の方針による）
- キーバッファとシフト状態（空にする）

残りの下位メモリは 0 で埋める。画面はテキスト消去・グラフィック非表示にしてから IPL に入る。

起動は、仮想ドライブ 0 の先頭セクタを読んで所定の番地に置き、ブートデバイスを設定して飛ぶ。

## 7. ホストサービス呼び出し

ゲストの要求をホスト世界で処理する手順。FDD BIOS もメニューもこの 1 本の経路を通る。

1. モニタが要求ブロック（機能番号、ゲストのレジスタ）を作る。書き込み系なら、ゲストのバッファを転送バッファへ複写する
2. ゲスト側のハードウェア状態を控え、ホスト側の状態に戻す（下表）
3. ホスト世界へ移り、C の受付関数を呼ぶ
4. 戻ったらゲスト側のハードウェア状態を復元する
5. 読み出し系なら転送バッファからゲストのバッファへ複写し、結果のレジスタと BIOS ワークエリアを書いてゲストへ戻る

| 切り替える状態 | FDD BIOS | メニュー |
| --- | --- | --- |
| 割り込みマスク | ○ | ○ |
| A20 | ○ | ○ |
| テキスト画面の内容と表示状態 | — | ○ |
| キーボードの押下状態の後始末 | — | ○ |

切り替える状態は表として持ち、項目を足せるようにする。画面を触らない FDD BIOS の経路は
短く保つ（アプリのロード中に画面がちらつかない）。

## 8. FDD BIOS エミュレーション

3 層に分ける。上 2 層がホスト世界の C、いずれもホスト OS 上で単体検証する。

| 層 | 役割 | 状態 |
| --- | --- | --- |
| BIOS 意味論 | INT 1Bh の機能番号ごとの動作。レジスタとステータスの組み立て、READ ID の巡回、複数通りデータの使い回し、マルチトラック | 未着手 |
| ドライブ | 仮想ドライブ 4 台ぶんの管理。イメージの出し入れ、媒体種別とデバイス種別の照合、書き込み禁止 | 未着手 |
| ディスクイメージ | 4 形式（内部では 5 種）を「トラックごとのセクタ ID 一覧＋データ位置」という 1 つの見え方に揃える | 実装・検証済み（[disk-image-formats.md](disk-image-formats.md)） |

ディスクイメージ層はセクタの ID（C・H・R・N）、密度、DDAM、収録時のステータス、複数通りの
データ、特殊読み込みを区別して持つ。標準的でない構造のディスクを NFD や FDD 形式で扱うには
これらが要る。FDI と RAW は一様な構造として同じ見え方に合成する。

### INT 1Bh について読み取ってあること

BIOS 意味論の層を書くときの出発点。どれも参考実装（NP2kai `bios/bios1b.c`）から読み取ったもので、
エミュレータが BIOS を代行するコードであって実機の ROM ではない。実機の資料で裏を取ってから使う。

| 項目 | 読み取った内容 |
| --- | --- |
| 入力 | AH = 機能（下位 4 ビット）と修飾ビット、AL = デバイス種別（上位ニブル）とユニット番号（下位 2 ビット）、BX = 転送バイト数、CL = シリンダ、DH = ヘッド、DL = セクタ、CH = セクタ長 N、ES:BP = バッファ |
| 機能番号 | 0 = シーク、1 = ベリファイ、2 = 診断のための読み込み、3 = 初期化、4 = センス、5 = 書き込み、6 = 読み込み、7 = シリンダ 0 へシーク、Ah = READ ID、Dh = フォーマット、Eh = 動作モードの設定。9h と Ch も分岐がある（中身は未読） |
| 修飾ビット | 10h = 先にシークする。80h = マルチトラック（ヘッド 0 のトラック終端を越えたらヘッド 1 へ続ける） |
| 戻り値 | AH = ステータス。20h 以上なら、スタックに積まれた FLAGS の CF を立てて戻る |
| 準備できていない | 60h |
| センス | 正常で 00h、書き込み禁止で 10h。AL のビット 7 が立つ種別では 01h を足す。立たない種別では、動作モードの領域（0000:0493 または 0000:05CA）のユニットごとのビットに応じて 01h・04h を足す。`(AX and 8F40h) = 8400h` の呼び出しでは 08h（1MB / 640KB 両用ドライブ）を足し、さらに AH のビット 6 が立っていて 1.44MB 対応なら 04h を足す |
| 読み込み・ベリファイの失敗 | 該当セクタなしなどで C0h、シークの失敗で E0h、形式のパラメータが引けないとき D0h |
| 初期化以外の全機能 | FDC の割り込みが割り込みコントローラでマスクされていると 40h |
| イメージが持つステータス | NFD のセクタ ID にある収録時の結果（byStatus）を、そのまま AH として返している |
| 結果の格納先 | 0000:0564 + ユニット番号 × 8 に、ST0・ST1・ST2・C・H・R・N・シリンダ番号の 8 バイト。ただしこの並びは参考実装の中で無効化されているコード片から読んだもので、有効な経路の書き込み内容は未読 |
| 割り込み待ちの印 | 完了時に 0000:055E（1MB 系）または 0000:055F（640KB 系）の、ユニットに対応するビットを落とす |
| 外付け ROM への振り分け | 0000:04B0 + デバイス種別（AL の上位ニブル）の 1 バイトが 0 でなければ、それを上位バイトとするセグメントの 0018h へ、レジスタを積んで飛ぶ。SCSI の種別は対象外 |
| IPL の起動 | [§12](#12-確度と検証計画) の表を参照 |

## 9. ポーズとディスク交換

- キーの検出: ゲスト（またはゲスト内で動く BIOS）がキーボードのデータポートを読むのをトラップし、
  実際に読んだ値をそのまま返しつつ、モニタ側でも押下状態を追う。ゲストに届くデータは変えない
- メニューへ移る時機: 検出した時点でゲストが割り込み処理の途中だと、そのままホストへ移ると
  ホスト側に割り込みが届かない。割り込みコントローラに処理中の割り込みが残っていない時点まで
  待ってから切り替える
- 画面: メニューはテキスト画面だけで描く。テキスト VRAM の表示範囲と、テキスト表示の状態
  （表示の有無、カーソル、スクロール設定、桁数・行数のモード）を退避し、閉じるときに戻す。
  グラフィック画面とパレットには触らない
- 再開時: メニュー中に離されたキーをゲストは見ていないので、押しっぱなしに見えないよう後始末をする
- メニューの機能: ドライブごとのイメージ差し替え・取り出し、ファイル選択、終了

ファイル選択はホスト世界の C で、MS-DOS のファイル検索を使って作る。

## 10. リセットと終了

- ゲストが CPU リセットをかけた（リセット用ポートへの書き込み、リセットベクタへの飛び込み）:
  仮想マシンを §6 の初期状態に作り直し、仮想ドライブの中身は入れたままで IPL からやり直す
- メニューから終了: ホスト世界へ移ったあと、ゲストが変えたハードウェアを MS-DOS が使える状態に
  戻す（割り込みマスク、タイマ、テキスト画面の再初期化、グラフィック非表示、音源の消音など。
  項目は表として持つ）。メモリとファイルを解放してプロンプトへ戻る

## 11. ソース構成

| 場所 | 内容 | 言語 |
| --- | --- | --- |
| `src/core/` | ホスト OS 上でも DOS 上でも同じソースでビルドする部分。ディスクイメージ層、ドライブ層、BIOS 意味論 | C（OS・コンパイラ依存なし、far ポインタなし） |
| `src/dos/` | DOS 依存の部分。ファイル入出力と転送バッファ（実装済み）、メニュー、起動時の検査（未着手） | C（gcc-ia16） |
| `src/mon/` | モニタ核。モード切替と例外の入口・出口、割り込みの反射（実装済み）。ゲスト用メモリの写像、I/O トラップ、世界の切替（未着手） | アセンブリ（gcc-ia16 付属のアセンブラ、Intel 記法）と C。ring 0 で動く C は `_r0.c` |
| `tools/` | 検証用イメージの生成、DOS 向けのビルド | Python / シェル |
| `tests/` | 試験プログラムと、ホスト OS 上・DOS 上での実行 | C / Python |

`src/core/` は int が 16 ビットの環境でも動くように書く（位置や大きさの計算は 32 ビット型で明示する）。

## 12. 確度と検証計画

方式が依って立つ事実と、その確度。「確認済み（エミュレータ）」は DOSBox 0.74-3 上で動かして
確かめたもので、実物の CPU や PC-98 では確かめていない。

| 記述 | 確度 | 根拠 / 確かめ方 |
| --- | --- | --- |
| INT 1Bh のデバイス種別（AL 上位ニブル）: 9 = 2HD、3・B = 1.44MB、1 = 2DD（1MB インタフェース経由）、7 = 2DD（640KB インタフェース）、5 = 2D、0・8 = SASI/IDE、2・A・C = SCSI | 未検証 | 参考実装（NP2kai `bios/bios1b.c`）を読んだ。実機 BIOS では確かめていない |
| デバイス種別 F の意味 | 未確認 | 資料が食い違う。参考実装の BIOS 部は 2HD の媒体として、同じ実装の FDI 読込と FDI の資料は 2DD として扱っている。実機の BIOS の資料で確かめる |
| INT 1Bh は AH にステータスを返し、AH ≥ 20h のときスタック上の FLAGS の CF を立てる | 未検証 | 同上 |
| INT 1Bh のヘッド番号は `(DH xor (AL >> 2)) and 1` | 未検証 | 同上 |
| FDC の割り込みがマスクされていると INT 1Bh は 40h を返す | 未検証 | 同上 |
| IPL の読み込み先は、1024 バイト/セクタの 2HD で 1FC0:0000（1024 バイト）、それ以外で 1FE0:0000（512 バイト）。ブートデバイスは 0000:0584 | 未検証 | 同上。実機の IPL 進入時のレジスタ値は未確認 |
| BIOS ワークエリアの番地（ディスク装備 0000:055C、結果領域 0000:0564〜、拡張メモリ量 0000:0401 ほか） | 未検証 | 参考実装（`bios/biosmem.h`）を読んだ |
| 仮想86モードからの割り込み・例外を、32 ビットの割り込みゲート経由で 16 ビットのコードセグメントのハンドラで受けられる | 確認済み（エミュレータ） | `tests/run_dos_tests.py mon`（DOSBox 0.74-3）。実物の CPU では確かめていない。以下「確認済み（エミュレータ）」は同じ意味 |
| IOPL=3 の仮想86モードでは CLI・STI・PUSHF・IRET がトラップせず、INT n は DPL=3 のゲートを直接通る | 確認済み（エミュレータ） | 同上。ゲートを DPL=0 にする、またはゲストを IOPL=0 で走らせると試験が落ちることも確かめた |
| 仮想86モードからの進入時のスタックの深さで、エラーコードの有無を見分けられる。同じ番号でも INT 0Dh は割り込みとして、HLT や特権命令は一般保護例外として届く | 確認済み（エミュレータ） | 同上。判定を逆にすると試験が落ちることも確かめた |
| ページを差し替えると、仮想86モードのゲストからは差し替え先が見え、書き込みも差し替え先に入る | 確認済み（エミュレータ） | 同上 |
| gcc-ia16 が通常の設定で出すコードは保護モードでは動かない（セグメントレジスタに任意の値を入れる）。`-mprotected-mode` を付け、ライブラリを呼ばなければ ring 0 で動く | 確認済み（エミュレータ） | 付けずに動かすと、ゲストの IP の値をセレクタとして読み込もうとする一般保護例外がモニタ内で起きた。付けたあとは起きない。コンパイラが別の形でセグメントレジスタを使う場合が残っていないかは確かめていない |
| gcc-ia16 の呼び出し規約では、AX・BX・CX・DX が破壊可、SI・DI・BP・ES が呼ばれる側の保存 | 未検証 | コンパイラのソース（`gcc/config/ia16/ia16.h` の `CALL_USED_REGISTERS`）を読んだ。ES を壊す関数を呼ぶと、呼び出し側の変数が化けるのを観測した |
| PC-98 の IRQ はベクタ 08h–17h に割り当てられている | 推測 | 記憶。資料と実機で確かめる |
| ROM 領域のページも、他のページと同じように RAM の写しへ差し替えられる。写しのリセットベクタを HLT にしておくと、FFFF:0000 への飛び込みが一般保護例外として届く | 確認済み（エミュレータ） | 同上。DOSBox は PC-98 ではないので、PC-98 の ROM の配置では確かめていない |
| MS-DOS がどのベクタを RAM 側へ付け替えているか | 未確認 | ホストのベクタ表をダンプする。エミュレータと実機の両方で、MS-DOS の版ごとに見る |
| §6-2 のシングルステップ追跡で ROM のエントリが得られる | 未確認 | 同上の環境で、得た番地が電源投入直後のベクタと一致するかを比べる |
| I/O ポートの番号（CPU リセット、A20、キーボード、テキスト GDC、モード設定）と、A0000 以降のメモリ配置 | 推測 | 記憶。実装前に資料で確かめ、番号はソースに出典つきで書く |
| gcc-ia16（6.3.0、binutils 2.39）で次ができる: small モデルの DOS 実行ファイル（MZ 形式）の生成、`__far` ポインタと `_dos_read` を使うコードのコンパイル、`src/core/` の警告なしのコンパイル、付属アセンブラでの 16/32 ビット混在コードと特権命令（LGDT・LIDT・LTR・CR0/CR3 への転送・32 ビットの IRET と far JMP）のアセンブル | 確認済み | 実際にコンパイル・アセンブルし、実行ファイルの先頭（MZ）と逆アセンブル結果を見た。いまは `tools/build16.sh` がこれらを毎回行っている |
| gcc-ia16 のメモリモデルは tiny / small / medium で、生成コードは 80286 まで | 未検証 | オプション定義（`gcc/config/ia16/ia16.opt`）と、付属ライブラリの構成一覧を読んだ |
| gcc-ia16 で生成した実行ファイルが DOS 上で動く。ディスクイメージ層と DOS 用の入出力層（転送バッファを別セグメントに置く）が、int 16 ビットの環境でホスト OS 上と同じ結果を出す | 確認済み | `tests/run_dos_tests.py`（DOSBox 0.74-3 上で 39 件）。16 ビットでだけ壊れる誤り（位置の計算を `unsigned` で行う）を入れると、ホスト OS 上では全件通り、DOS 上では NFD r0 の 6 件が落ちることを確かめた。確かめたのは機種に依らない DOS プログラムとしての動作で、PC-98 上の DOS では走らせていない |
| 16 ビット幅での乗算あふれは、gcc-ia16 のコンパイル時の警告では捕まらない | 確認済み | 小さな例をコンパイルして確かめた。同じ誤りのうち型変換を伴うものはホスト OS 側の警告で止まるが、止まらない書き方もある。実行での試験が要る |
| DOSBox 0.74-3 は PC-98 を再現しない | 未検証 | 付属マニュアルの機種一覧に PC-98 がない。386 の保護モード・仮想86・ページングの確認と、機種に依らない DOS プログラムの試験に使う |
| NP21/W の BIOS はエミュレータ内蔵の実装で、BIOS ワークエリアを物理番地で直接読み書きする（ページングを通らない） | 未検証 | 同系統の NP2kai のソース（`bios/biosmem.h`）では、BIOS ワークエリアの参照が物理メモリの配列への直接アクセスになっている。NP21/W で確かめていない。事実なら §2 の D7 が要る |

検証環境は 4 段を想定する。

| 環境 | 確かめられること | 状態 |
| --- | --- | --- |
| ホスト OS | `src/core/` の論理 | 稼働中 |
| DOSBox 0.74-3 | 16 ビットでの動作、DOS 依存部、386 の保護モード・仮想86・ページング（機種に依らない範囲）。CPU の再現が実物とどこまで一致するかは別途の問題 | 稼働中（画面なしで自動実行） |
| NP21/W | PC-98 のハードウェアに依る部分。ただし BIOS は内蔵の実装で、実機の ROM とは経路が違う | 未整備 |
| 実機 | すべて | 未着手 |

## 13. 未決の設計判断

提案と、後から変えるときの値段。決まったら [spec.md](spec.md) の確定事項へ移す。

| 項目 | 提案 | 理由 | 後から変える値段 |
| --- | --- | --- | --- |
| ゲストから HDD が見えるか | 見せない。INT 1Bh の HDD 向け呼び出しは「装置なし」を返す | アプリの誤動作や意図しない書き込みからホストの HDD を守る。HDD を使うベアメタルアプリは想定していない | 小。INT 1Bh の振り分け 1 箇所と装備情報の初期値。ただし I/O ポート直叩きまでは初版では塞がない |
| ゲストに拡張メモリを見せるか | 初版は見せない（拡張メモリ 0 として報告） | 見せるには INT 1Fh のメモリ転送機能の代行が要り、初版の規模が増える。拡張メモリを必要とするベアメタルアプリがどれだけあるかは未確認で、動かしたいタイトルの動作要件を見れば決まる | 中。確保量の追加、ページ表、INT 1Fh の代行 |
| アプリの CPU リセット | 仮想マシンを再起動 | 実機でリセットボタンを押したのと同じ結果になる | 小。分岐 1 箇所 |
| 書き込みの反映 | BIOS 呼び出しのたびにファイルへ書く | 電源断やハングで書き込みが失われない。イメージをメモリに抱えないので必要メモリが増えない | 中。遅延書き込みにするなら、書き戻しの時機（交換時・終了時）と失敗時の扱いが増える |
| 仮想ドライブの台数 | 器は 4 台、既定は 2 台 | BIOS のユニット番号が 2 ビット | 小。既定値のみ |
| FDC を直接操作するアプリ | 初版は対象外 | FDC と DMA のエミュレーションが別に要る。I/O トラップの仕組みはあるので後から足せる | 大（新規モジュール） |
