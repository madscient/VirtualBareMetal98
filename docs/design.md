# 設計

読者: 開発者・AI。方式と、その決定の理由・前提を書く。要件は [spec.md](spec.md)。

動かして確かめてあるのは、ディスクイメージ層（§8 の最下層）と、モニタ核のうち機種に依らない
部分（モード切替、例外の入口、割り込みの反射、ゲスト用メモリの写像、I/O トラップ）である。
それ以外は設計だけで、ハードウェアや CPU の振る舞いについての記述の確度は §12 にまとめてある。

## 1. 全体像

```
        ホスト世界                       モニタ                     ゲスト世界
   ┌───────────────────┐         ┌───────────────┐         ┌─────────────────────┐
   │ MS-DOS (リアルモード) │ ◀─切替─▶ │ 保護モード ring 0 │ ◀─例外─▶ │ 仮想 PC-98 (仮想86モード) │
   │  ファイル入出力        │         │  割り込みの反射   │  割込み  │  ベアメタルアプリ       │
   │  FDD BIOS の意味論    │         │  BIOS の横取り    │         │  実機の ROM BIOS      │
   │  ディスク交換メニュー   │         │  ページング       │         │                     │
   └───────────────────┘         └───────────────┘         └─────────────────────┘
        本来の下位 640KB              両方の世界の外に常駐          拡張メモリ上の別の 640KB
```

ホストの MS-DOS とゲストのアプリは、どちらも「下位 1MB を丸ごと自分のもの」として動く。
同じ番地を二者が使うので、ゲストには拡張メモリ上に別の 640KB を与え、ページングでそれを
下位番地に見せる。ホストの MS-DOS は元の場所に手つかずで残るので、イメージファイルの
読み書きにも、終了後のプロンプト復帰にもそのまま使える。

同時に走るのは常に片方だけで、切り替えはモニタが行う。

ゲストに見せる構成は PC-9801VM 相当（[spec.md](spec.md)）。ハードウェアは実物をそのまま使い、
差し替えるのは構成情報（§6）、スイッチの読み出し値（§15）、V30 固有命令の代行（§14）である。

## 2. 決定と前提

| # | 決定 | 理由 | 前提（崩れたら見直す） |
| --- | --- | --- | --- |
| D1 | ホスト世界は仮想86にせず、リアルモードに戻して走らせる | HIMEM やディスク BIOS、常駐物が特権操作や保護モードを使っても、何も仮想化せずに動く。モニタが面倒を見る対象がゲストだけになる | ホストがリアルモードで起動している。VCPI 対応時は「ホストへ移る／戻る」の 2 手続きだけを VCPI 経由の実装に差し替える |
| D2 | ゲストは IOPL=3 の仮想86で動かし、I/O ポートは原則素通しにする | ベアメタルアプリは割り込みの禁止・許可や I/O を多用する。それを毎回トラップすると遅い。ゲストは 1 つだけで CPU を分け合わないので、割り込みフラグを仮想化する必要がない | ゲストが 1 つ。ホストとゲストが同時に走らない |
| D3 | BIOS の横取りは、ROM のエントリ先頭 1 バイトを HLT に差し替えた「写しページ」で行う（§5） | INT 命令で呼んでも、ベクタを読んで far call しても、ゲストが自前のフックを挟んでも、最後に ROM へ入る瞬間に捕まえられる | ROM エントリの番地が分かる（§6）。分からない機種では INT 命令の時点で横取りする方式に落とす |
| D4 | FDD BIOS の意味論はホスト世界の C で実行し、モニタはゲストのメモリとの複写だけを受け持つ | 論理の大半を、同じソースのままホスト OS 上で検証できる | BIOS 呼び出し 1 回につき世界の切替 1 往復、という所要時間が許容できる（未計測） |
| D5 | セクタデータの受け渡しは、ホストの下位メモリに確保した 64KB の転送バッファを介す | リアルモードのホストからはゲストのメモリ（拡張メモリ上）に届かない。INT 1Bh の転送長は 16 ビットなので、64KB あれば 1 回の呼び出しを 1 往復で済ませられる | — |
| D6 | イメージの管理情報は常駐させず、トラック単位で読む | NFD r0 のヘッダは 68KB あり、near データに収まらない | ホストのファイルアクセスが十分速い（HDD 上のイメージを想定） |
| D8 | 例外・割り込みの判断は ring 0 で動く C で書き、アセンブリはモード切替と入口・出口だけにする | 判断の部分が読みやすく、試験を足しやすい。アセンブリの量が減る | 保護モードのコード・データセグメントを、実行ファイルのそれと同じ場所を指す 16 ビットセグメントにしてあること（§4）。割り込み 1 回あたりに C の関数呼び出しが挟まる時間が許容できること（未計測） |
| D9 | 「PC-9801VM 相当」は、ハードウェアは実物のまま、ゲストから見える構成情報（BIOS ワークエリアの機種判別・装置フラグ、DIP スイッチの読み出し値、メモリスイッチ、拡張メモリ量）を揃えることで実現する | 表示や音の再現は仮想86モードでの直接実行と相容れない。PC-9801VM 向けのアプリは、その上位互換であるホストのハードウェアの範囲で動く | 対象アプリが、ホストにあって PC-9801VM にない機能の不在に依存しないこと。依存するものが出たら、該当する I/O をトラップして隠す |
| D10 | V30 エミュレーションは、V30 固有の命令が 386 で例外になることを利用して、例外のときだけ代行する（§14） | 命令単位の解釈実行にすると仮想86モードの速さが失われる。固有命令は使われる頻度が低い | 対象アプリが、例外にならない差（§14「直せない差」）に依存しないこと。ホストの CPU の世代によって届かない命令があることを受け入れること |
| D11 | ゲストの HLT は、ring 0 で本物の HLT を実行して次の割り込みを待ち、その割り込みを「HLT の次の命令」を戻り先にしてゲストへ渡す。割り込み禁止のままの HLT は、起こせる割り込みがないのでゲストの停止としてホストへ返す（ホストは VM メニューを開く。[spec.md](spec.md)） | 命令を進めずに戻す方式だと、割り込みのあとゲストが HLT に戻って再び止まり、「HLT で 1 回の割り込みを待つ」コードが先へ進まない。HLT を無視する方式だと待たずに進んでしまう | ring 0 で待っている最中の割り込み進入を、入口がスタックの位置で見分けられること（§4）。NMI は考えない |
| D7（見送り） | ゲスト世界の 0 番ページ（割り込みベクタと BIOS ワークエリア）だけを物理の 0 番ページに写像し、世界の切替のたびに入れ替える案 | BIOS を内蔵の実装で代行するエミュレータが BIOS ワークエリアを物理番地で読み書きするなら要る、と考えていた。NP21/W で確かめたところ、内蔵 BIOS（INT 18h AH=03h）の書き込みはページングを通ってゲスト側のメモリに入った（§12）。よって不要 | 他の BIOS 機能や別のエミュレータで物理番地の読み書きが見つかったら復活させる |

## 3. メモリとページング

ゲスト世界の線形アドレスの割り当て。

| 線形アドレス | 写像先 | 備考 |
| --- | --- | --- |
| 00000–9FFFF | ゲスト用に確保した拡張メモリ | 割り込みベクタと BIOS ワークエリアもここに入る |
| A0000–FFFFF | 同じ番地の実メモリ | VRAM と ROM は実物を共有する。横取り用に差し替えたページだけが RAM の写し |
| 100000–10FFFF | A20 の状態に応じて、00000–0FFFF と同じページ／何もなし | A20 を閉じた実機と同じ折り返しを再現する |
| モニタ用の高位アドレス | モニタのコード・データ・GDT・IDT・TSS・ページテーブル | ゲストの 1MB の外に置き、ゲストからは見えない |

- ゲスト用メモリは XMS（HIMEM.SYS）があればそこから確保して固定する。なければ BIOS の拡張メモリ量から直接切り出す。確保経路は差し替えられる形にする（VCPI 用の 3 つ目が来る）
- モニタは 16 ビットのコードセグメントで書き、必要な箇所だけ 32 ビットのオペランドを使う。実行ファイルを 16 ビットの DOS プログラム 1 本にまとめるため

## 4. 割り込み・例外・特権命令

- IDT の全ベクタを 32 ビットの割り込みゲート（DPL=3）にし、ベクタ番号を積んで共通処理へ入る
- 共通処理は原則として「ゲストの割り込みベクタ表を引いて、ゲストのスタックに FLAGS・CS・IP を積み、そこへ飛ばす」。ハードウェア割り込みもソフトウェア割り込みも同じ扱い
- PC-98 では IRQ のベクタ（08h–17h）が CPU 例外の番号と重なる。仮想86モードからの進入は必ず同じスタック位置から始まるので、エラーコードが積まれているか（＝スタックの深さ）で例外と割り込みを見分ける
- 進入の形は 3 つ: 仮想86モードからのエラーコードなし／あり、そして ring 0 で HLT 待ちの最中（D11）。いずれもスタックの位置で見分ける。それ以外の位置から来たものはモニタ自身の例外として扱う
- 一般保護例外で扱うもの: HLT（割り込み待ち、または §5 の横取り印）、トラップ指定した I/O ポート、V30 固有命令のうち 386 では特権命令に当たるもの（§14）、DPL=0 のゲートへの INT n（§14）。それ以外は異常としてゲストを止めて報告する
- 未定義命令例外（ベクタ 6）: V30 固有命令なら代行する（§14）。それ以外はゲストの INT 6 へ反射する
- ゼロ除算例外（ベクタ 0）: `-v30 on` では戻り番地を V30 の規則に直して反射する（§14）
- モニタ自身の実行中に例外が起きたら、状態を表示して MS-DOS に戻る

ring 0 で動く C には制約がある。守られないと保護モードで例外になるが、リアルモードでは
何も起きないので、ビルド時に検査する（`tools/build16.sh`）。

- 名前が `_r0.c` で終わるファイルに置き、保護モード向けの設定（`-mprotected-mode`）でコンパイルする。
  通常の設定で gcc-ia16 が出すコードは、セグメントレジスタを値の置き場として使う
- C ライブラリとコンパイラの補助関数（32 ビットのシフト・乗除算、構造体の複写が化ける `memcpy` など）を
  呼ばない。外部への参照は `mon_` で始まる名前だけにする
- far ポインタを使わない。ゲストのメモリは線形番地を指定する補助関数で読み書きする

C から呼ぶアセンブリの関数は、gcc-ia16 の規約に合わせて SI・DI・BP・ES を保存する
（ES は「呼ばれる側が保存するレジスタ」で、コンパイラが呼び出しをまたいで値を置く）。

トラップする I/O ポート（最小限）:

| ポート | 目的 |
| --- | --- |
| CPU リセット | 仮想マシンの再起動として扱う（§10） |
| A20 制御 | §3 の折り返しを切り替える |
| キーボードのデータ・ステータス | ホットキーの検出と、モニタが先に読み取った値の再提供（§9） |
| DIP スイッチの読み出し | 設定された値を返す（§15） |
| テキスト表示まわりの書き込み専用レジスタ | 値を控えておき、メニューを閉じるときに戻す（§9） |

## 5. BIOS 呼び出しの横取り

ROM BIOS のエントリがあるページを RAM に写し、エントリ先頭の 1 バイトを HLT に書き換えて、
ゲスト世界ではその写しを見せる。ゲストがそこへ来ると一般保護例外になるので、番地が登録済みの
横取り印と一致すればモニタが処理する。処理後は、ゲストのスタックに積まれている割り込みフレームを
使って呼び出し元へ戻す。

横取りの対象:

| 対象 | 処理 |
| --- | --- |
| INT 1Bh（ディスク BIOS） | デバイス種別がフロッピーならイメージで応える（§8）。HDD の種別には「装置なし」を返す（ホストの HDD は見せない） |
| リセットベクタ FFFF:0000 | 仮想マシンの再起動（§10） |
| INT 1Fh のうち保護モードを使う機能 | 拡張メモリは見せないので、機能ごと失敗を返す |

横取りの表は、線形番地と識別子の組を並べたもの（`mon_hook_add`。上限は定数）。登録のない HLT は
本物の HLT として扱う（D11）。

いまの実装（`src/dos/vbm98.c`）は、INT 1Bh については ROM のエントリではなく、ゲストのベクタ表の
1Bh を BASIC ROM 領域の末尾（F7000h）に置いた HLT のページへ向けている。ROM エントリの番地に
依存せず、どの機種でも同じに動くため。ROM エントリを far call で呼ぶアプリには効かない。
D3 の方式（ROM の写し）に切り替えるかは、そういうアプリが見つかってから決める。リセットベクタは
D3 のとおり ROM の写しで横取りしている。

## 6. ゲストの初期状態

ゲストには「電源投入後、IPL に入る直前」の PC-98 を見せる必要がある。ところがホストは MS-DOS が
動いている状態で、割り込みベクタの一部は MS-DOS やドライバ（RAM 上のコード）を指している。
ゲストの 640KB にそのコードは存在しないので、そのままは渡せない。

割り込みベクタ（256 本とも同じ規則で決める）:

1. ホストのベクタが ROM 領域を指していれば、そのまま使う
2. RAM を指している場合、ROM のエントリを突き止められたらそれを使う。方法は、ホスト世界で
   その割り込みを無害な機能番号で 1 回呼び、シングルステップで追って最初に ROM へ入った番地を採る
3. 突き止められなければ、ROM 内の IRET 1 バイトを指す。それが IRQ のベクタなら、ゲストの
   割り込みマスクの初期値でその IRQ を閉じる

BIOS ワークエリア（0000:0400–05FF）はホストのものを写し、次を直す。

- ブートデバイス、ディスク装備情報（FDD 2 台、HDD なし）
- 拡張メモリ量（0）
- 機種判別と装置の有無のフラグ（機種は PC-9801VM、装置の有無はホストの実物に合わせる。値は資料で確かめて決める）
- DIP スイッチ・メモリスイッチから ITF が導く設定（§15）
- キーバッファとシフト状態（空にする）

メモリスイッチは実物のテキスト VRAM の中にあってゲストと共有されるので、ここで設定値を書き込む（§15）。

残りの下位メモリは 0 で埋める。画面はテキスト消去・グラフィック非表示にしてから IPL に入る。

起動は、仮想ドライブ 0 の先頭セクタを読んで所定の番地に置き、ブートデバイスを設定して飛ぶ。

いまの実装（`vbm98.c`）はこのうち、ベクタ表とワークエリアの写し、INT 1Bh のベクタの差し替え、
装備情報（FDD 2 台、HDD なし）、起動装置、IPL の読み込み、ベクタの規則のうち 1 と 3 の簡略版
（RAM を指す 00h〜1Fh のベクタは、横取り印へ向けて「IRQ なら EOI を出して戻る」）、表示系の初期化
（§16）、メモリスイッチの書き込み（`-memsw`）、テキスト画面の消去まで。規則 2（ROM エントリ探し）、
機種判別のフラグ、DIP スイッチの反映、キーバッファの消去は未実装。ハードウェア割り込みは、ゲストの
割り込みマスクのままゲストへ届く。マスクの初期値はホストの現在値で、NP2 系の ITF が電源投入時に書く
7Dh/71h と同じ（確認済み: NP2kai `bios/bios.c` の `bios_itfprepare` を読んだ。実機の ITF も同じ値かは
未検証）。

## 7. ホストサービス呼び出し

ゲストの要求をホスト世界で処理する手順。FDD BIOS もメニューもこの 1 本の経路を通る。

1. モニタが要求ブロック（機能番号、ゲストのレジスタ）を作る。書き込み系なら、ゲストのバッファを転送バッファへ複写する
2. ゲスト側のハードウェア状態を控え、ホスト側の状態に戻す（下表）
3. ホスト世界へ移り、C の受付関数を呼ぶ
4. 戻ったらゲスト側のハードウェア状態を復元する
5. 読み出し系なら転送バッファからゲストのバッファへ複写し、結果のレジスタと BIOS ワークエリアを書いてゲストへ戻る

| 切り替える状態 | FDD BIOS | メニュー |
| --- | --- | --- |
| 割り込みマスク | ○ | ○ |
| A20 | ○ | ○ |
| テキスト画面の内容と表示状態 | — | ○ |
| キーボードの押下状態の後始末 | — | ○ |

切り替える状態は表として持ち、項目を足せるようにする。画面を触らない FDD BIOS の経路は
短く保つ（アプリのロード中に画面がちらつかない）。

いまの実装は、モニタが `mon_run` から戻ることで世界を切り替え、ゲストのメモリとの複写は
XMS の転送（機能 0Bh）でホスト側から行っている。切り替える状態は割り込みマスクだけ。
転送バッファ（D5）は fdbios と共有している。

切り替えの規則: **ゲストの割り込みマスクが効いている間に、ホストのベクタ表で割り込みを受けては
いけない。** マスクの入れ替えと `mon_run` の出入りは割り込み禁止で行い、ゲスト世界（モニタの IDT）に
入ってから許可する。守らないと、ゲスト宛ての割り込みがホストの既定ハンドラに食われ、ハンドラ側で
再許可する種類の割り込み（CRTV = VSYNC）はそこで途絶える（確認済み: NP21/W でイース2 の VSYNC が
INT 1Bh の処理をまたいだ直後に止まり、禁止を入れると続いた）。

## 8. FDD BIOS エミュレーション

3 層に分ける。上 2 層がホスト世界の C、いずれもホスト OS 上で単体検証する。

| 層 | 役割 | 状態 |
| --- | --- | --- |
| BIOS 意味論 | INT 1Bh の機能番号ごとの動作。レジスタとステータスの組み立て、READ ID の巡回、複数通りデータの使い回し、特殊読み込み、マルチトラック、64KB 境界、ワークエリアへ書く内容 | 実装・検証済み（`src/core/fdbios.c`。ホスト OS 上 66 項目） |
| ドライブ | 仮想ドライブの管理（器は 4 台ぶん、ゲストに見せるのは 2 台）。媒体種別とデバイス種別の照合、書き込み禁止、ヘッドの位置 | `fdbios.c` の `struct fdb` に含めた。イメージの出し入れは `img[]` の差し替え |
| ディスクイメージ | 4 形式（内部では 5 種）を「トラックごとのセクタ ID 一覧＋データ位置」という 1 つの見え方に揃える | 実装・検証済み（[disk-image-formats.md](disk-image-formats.md)） |

ディスクイメージ層はセクタの ID（C・H・R・N）、密度、DDAM、収録時のステータス、複数通りの
データ、特殊読み込みを区別して持つ。標準的でない構造のディスクを NFD や FDD 形式で扱うには
これらが要る。FDI と RAW は一様な構造として同じ見え方に合成する。

BIOS 意味論の層（`fdb_call`）は、ゲストのレジスタを受け取り、ステータス（AH）と、転送バッファとの間で
動かす長さ、BIOS ワークエリアへ書く内容（装備情報、割り込み待ちの印、動作モード、結果の 8 バイト）を
返す。ゲストのメモリには触れない。読み込み系では呼んだあとに転送バッファの先頭から `xfer` バイトを
ゲストの ES:BP へ、書き込み系では呼ぶ前にゲストの ES:BP から BX バイトを転送バッファへ写す
（`fdb_direction`）。この分担により、意味論はホスト OS 上で全部試験できる。

### INT 1Bh について読み取ってあること

BIOS 意味論の層の根拠。参考実装（NP2kai `bios/bios1b.c`）と、その挙動を踏襲した別実装
PC98_Open_BIOS（0BSD、`src/int1b.asm` と `tests/test_fdd_bios.py`）から読み取った。
どちらもエミュレータや互換 BIOS であって実機の ROM ではない。両者は一致しているが、
実機の資料で裏を取ったものではない。

| 項目 | 読み取った内容 |
| --- | --- |
| AH の修飾ビット | 10h = 先にシーク、20h = 削除データを飛ばす、40h = MFM、80h = マルチトラック |
| デバイス種別（AL 上位ニブル） | 9 = 1MB インタフェースの 2HD、3・B = 1.44MB モード、1 = 1MB インタフェースで 2DD 媒体、7 = 640KB インタフェースの 2DD、F = 640KB インタフェースで 2HD 媒体、5 = 640KB インタフェースの 2D（倍ステップ） |
| ステータス | 00 正常、10 書き込み禁止（センス）、20 DMA 境界、30 トラック終端を越えた、40 装置なし、50 オーバーラン、60 準備できていない、70 書き込み禁止、A0 ID の CRC、B0 データの CRC、C0 該当セクタなし、D0 シリンダ違い、E0 アドレスマークなし |
| 結果の格納 | 0564h + ユニット × 8 に ST0 ST1 ST2 C H R N NCN。R は FDC の結果と同じく「次のセクタ」 |
| AL のビット 2 | 物理ヘッドを DH から反転する（`hd = (DH xor (AL >> 2)) and 1`）。ID の照合は DH のまま |

本実装で決めたこと（資料に無い、または資料どうしで違うところ）:

- 収録ステータスが 20h 以上のセクタは、データを渡したうえでそのステータスで打ち切る（参考実装は最後のセクタの値を返すだけ）
- 複数通りのデータを持つセクタは、読むたびに次の通りを返す
- 特殊読み込みの項があれば、同じ命令・同じ ID のセクタより優先する（NFD r1 の資料のとおり）
- ID の照合は C・H・R・N すべて。R が合って C が違えば D0h（FDC と同じ。参考実装は R しか見ない）
- トラック終端を越えて MT なしなら 30h
- READ ID は MFM 指定（AH ビット 6）がなければ E0h（参考実装と同じ）
- フォーマットは一様な形式（RAW・FDI）だけ。他の形式は D0h
- 09h・0Ch（削除データの書き込み・読み込み）は 05h・06h と同じ扱い。未対応の機能番号は 60h（参考実装と同じ）
- 動作モード（0493h・05CAh）の初期値は 33h（資料なし）

以下は参考実装だけから読み取った、より細かい事項。

| 項目 | 読み取った内容 |
| --- | --- |
| 入力 | AH = 機能（下位 4 ビット）と修飾ビット、AL = デバイス種別（上位ニブル）とユニット番号（下位 2 ビット）、BX = 転送バイト数、CL = シリンダ、DH = ヘッド、DL = セクタ、CH = セクタ長 N、ES:BP = バッファ |
| 機能番号 | 0 = シーク、1 = ベリファイ、2 = 診断のための読み込み、3 = 初期化、4 = センス、5 = 書き込み、6 = 読み込み、7 = シリンダ 0 へシーク、Ah = READ ID、Dh = フォーマット、Eh = 動作モードの設定。9h と Ch も分岐がある（中身は未読） |
| 修飾ビット | 10h = 先にシークする。80h = マルチトラック（ヘッド 0 のトラック終端を越えたらヘッド 1 へ続ける） |
| 戻り値 | AH = ステータス。20h 以上なら、スタックに積まれた FLAGS の CF を立てて戻る |
| 準備できていない | 60h |
| センス | 正常で 00h、書き込み禁止で 10h。AL のビット 7 が立つ種別では 01h を足す。立たない種別では、動作モードの領域（0000:0493 または 0000:05CA）のユニットごとのビットに応じて 01h・04h を足す。`(AX and 8F40h) = 8400h` の呼び出しでは 08h（1MB / 640KB 両用ドライブ）を足し、さらに AH のビット 6 が立っていて 1.44MB 対応なら 04h を足す |
| 読み込み・ベリファイの失敗 | 該当セクタなしなどで C0h、シークの失敗で E0h、形式のパラメータが引けないとき D0h |
| 初期化以外の全機能 | FDC の割り込みが割り込みコントローラでマスクされていると 40h |
| イメージが持つステータス | NFD のセクタ ID にある収録時の結果（byStatus）を、そのまま AH として返している |
| 結果の格納先 | 0000:0564 + ユニット番号 × 8 に、ST0・ST1・ST2・C・H・R・N・シリンダ番号の 8 バイト。ただしこの並びは参考実装の中で無効化されているコード片から読んだもので、有効な経路の書き込み内容は未読 |
| 割り込み待ちの印 | 完了時に 0000:055E（1MB 系）または 0000:055F（640KB 系）の、ユニットに対応するビットを落とす |
| 外付け ROM への振り分け | 0000:04B0 + デバイス種別（AL の上位ニブル）の 1 バイトが 0 でなければ、それを上位バイトとするセグメントの 0018h へ、レジスタを積んで飛ぶ。SCSI の種別は対象外 |
| IPL の起動 | [§12](#12-確度と検証計画) の表を参照 |

## 9. ホットキーとディスク交換

ホットキーは [spec.md](spec.md) の 5 つ（CTRL + GRPH + DEL / テンキーの 0 / テンキーの 1 / COPY / STOP）。

- キーの検出: キーボードの割り込み（IRQ1）はモニタが先に受ける（IDT は全ベクタがモニタのもの）。
  モニタがデータポートを読んで記録し、CTRL と GRPH の押下状態を追う。ホットキーでなければ割り込みを
  ゲストへ反射し、ゲストがデータポートを読むのをトラップして記録した値を返す（ステータスポートも、
  記録した値が未読のあいだは「受信あり」を返す）。ホットキーなら反射せず、モニタが割り込み
  コントローラに EOI を送って、ゲストには何も届けない
- メニューへ移る時機: 検出した時点でゲストが割り込み処理の途中だと、そのままホストへ移ると
  ホスト側に割り込みが届かない。割り込みコントローラに処理中の割り込みが残っていない時点まで
  待ってから切り替える
- 画面: メニューはテキスト画面だけで描く。テキスト VRAM の表示範囲と、テキスト表示の状態
  （表示の有無、カーソル、スクロール設定、桁数・行数のモード）を退避し、閉じるときに戻す。
  グラフィック画面とパレットには触らない
- 再開時: メニュー中に離されたキー（CTRL・GRPH を含む）をゲストは見ていないので、押しっぱなしに
  見えないよう、離されたキーの break コードを割り込みの反射の仕組みで 1 つずつゲストへ届ける
- VM メニュー（CTRL + GRPH + DEL）の項目: ドライブ 0 の取り出し・入れ替え、ドライブ 1 の取り出し・入れ替え、
  スクリーンショット（§17）、終了。各項目は対応するホットキーで直接も呼べる
- 取り出し・入れ替え: ファイル選択に「取り出すだけ（空にする）」の選択肢を含める。
  選択はホスト世界の C で、MS-DOS のファイル検索を使って作る
- 終了（CTRL + GRPH + STOP）: 問い合わせに応じたときだけ §10 の終了処理へ進む。そうでなければ再開する

いまの実装（`vbm_r0.c` の `kbd_irq`、`vbm98.c`）は「キーの検出」と COPY（スクリーンショット、§17）まで。
5 つのホットキーは `X_HOTKEY_*` として `mon_run` から戻るが、STOP は問い合わせなしにゲストの様子を表示して
終わり、DEL・テンキーの 2 つは「未実装」と表示して再開する。メニュー・画面の退避・break コードの再送は
未実装。開発用に `-stopkey` / `-shotkey <スキャンコード>` で STOP / COPY の代わりのキーを足せる（試験に使う
エミュレータのキー配列で送れないため）。

## 10. リセットと終了

- ゲストが CPU リセットをかけた（リセット用ポートへの書き込み、リセットベクタへの飛び込み）:
  仮想マシンを §6 の初期状態に作り直し、仮想ドライブの中身は入れたままで IPL からやり直す
- メニューから終了: ホスト世界へ移ったあと、ゲストが変えたハードウェアを MS-DOS が使える状態に
  戻す（割り込みマスク、タイマ、テキスト画面の再初期化、グラフィック非表示、音源の消音など。
  項目は表として持つ）。メモリとファイルを解放してプロンプトへ戻る

## 14. V30 エミュレーション

ゲストに見せる CPU は V30（[spec.md](spec.md)）。ホストは 386 以上なので、V30 にあって 386 にない
命令をモニタが代行し、386 にあって V30 にない振る舞いの一部を V30 に合わせる。CPU を解釈実行する
のではなく、該当する命令が例外になったときだけ介入する（D10）。したがって、例外にならない差は直せない。

以下のオペコードと 386 以降での扱いは記憶で書いている（§12）。実装前に資料で確かめる。

### 代行する命令

V30 固有の命令は 0Fh で始まる。386 ではこの並びが別の命令（特権命令または未定義命令）に当たるので、
一般保護例外か未定義命令例外としてモニタに届く。モニタは CS:IP から命令を読み直して代行し、
IP を進めてゲストへ戻る。

| V30 の命令 | バイト列 | 386 での扱い（届き方） |
| --- | --- | --- |
| TEST1 / CLR1 / SET1 / NOT1（ビット操作。回数は CL または即値） | 0F 10〜1F | 未定義命令例外。ただし Pentium Pro 以降では 0F 18〜1F が無動作命令として実行され、届かない |
| ADD4S / SUB4S / CMP4S（パック BCD 文字列の加減算・比較） | 0F 20 / 22 / 26 | 制御レジスタの転送（特権命令）と解釈され、一般保護例外 |
| ROL4 / ROR4（ニブルの回転） | 0F 28 / 2A | 未定義命令例外。SSE を持つ CPU では CR4 の OSFXSR を 0 にしておけば未定義命令例外になる |
| INS / EXT（ビットフィールドの挿入・抽出） | 0F 31 / 33 / 39 / 3B | 386 では未定義命令例外。Pentium 以降では 0F 31 が RDTSC として実行されるので、CR4 の TSD を立てて一般保護例外にする。0F 33 は RDPMC で、既定で一般保護例外 |
| BRKEM（8080 エミュレーションモードへ） | 0F FF | 未定義命令例外。代行せず、ゲストを止めて報告する |

### 合わせる振る舞い

| 差 | 対応 |
| --- | --- |
| ゼロ除算例外の戻り番地: 8086/V30 は次の命令、286 以降は当該命令 | `-v30 on` ではベクタ 0 の反射時に IP を命令の後ろへ進める。命令長は CS:IP から読み解く |
| 未定義命令: V30 は INT 6 を発生する | 代行できない命令はゲストの INT 6 へ反射する（386 の未定義命令例外も同じ経路） |

### 直せない差

| 差 | 理由 |
| --- | --- |
| REPC / REPNC プリフィクス（64h / 65h） | 386 では FS / GS のセグメントオーバーライドとして例外なく実行される |
| FPO2（66h / 67h） | 386 ではオペランドサイズ / アドレスサイズのプリフィクス |
| シフト回数のマスク（286 以降は下位 5 ビットに切る） | 例外にならない。V30 が切らないかどうか自体も未確認 |
| PUSH SP が積む値 | 例外にならない |
| 8080 エミュレーションモード | 別の CPU の解釈実行になる。対象外 |
| 386 以降にしかない命令をゲストが実行した場合 | そのまま実行される。V30 で動かないという事実は再現しない |
| 実行速度 | spec でサイクル正確性は担保しない |

ホストの CPU の世代で、届く命令の範囲が変わる（上の表）。起動時に世代を見分け（EFLAGS の AC / ID
ビット、CPUID）、CR4 を設定できるものは設定し、残りは「この CPU では代行できない命令」として表示する。
NP21/W では SSE の命令が CR4 に関係なく実行されるので、0F 10〜1F・28・2A の代行は効かない（§12）。

### 例外とソフトウェア割り込みの見分け

ベクタ 6（未定義命令）と 0（ゼロ除算）は、ゲストの `INT 6` / `INT 0` 命令でも同じベクタに届く。
例外なら代行や IP の補正をし、命令なら反射するだけ、と処理が分かれるので見分けが要る。
提案: この 2 つだけゲートを DPL=0 にする。仮想86モードからの `INT n` は DPL が足りず一般保護例外になり、
エラーコード（ベクタ×8+2）でどのベクタかが分かるので、モニタが IP を命令の後ろへ進めて反射する。
例外は直接そのベクタへ届く。この 2 つは IRQ のベクタ（08h〜17h）と重ならない。確度は §12。

### 実装の置き場所と検証

ring 0 で動く C（`_r0.c`）。命令の読み解きとオペランドの読み書きは `mon_peek` / `mon_poke` で行う。
検証は、V30 固有の命令を含むゲストコードを DOSBox 上のモニタで走らせ、結果をホスト OS 上で計算した
期待値と比べる。DOSBox と NP21/W が該当するバイト列で例外を起こすかは未確認（§12）。

## 15. スイッチの反映

### DIP スイッチ

実機では I/O ポートで読める（ポート番号とビット割り当ては §12: 推測）。ゲストがそのポートを読むのを
トラップし、設定された値（省略時はホストの現在値）を返す。ITF がスイッチから導いて BIOS ワークエリアや
ハードウェアに設定する内容（画面モード、GDC クロックなど）は、§6 の初期状態の作成でモニタが同じことをする。
どのスイッチが何に影響するかの一覧は、資料で確かめてから書く。

### メモリスイッチ

テキスト VRAM の属性面の末尾 A3FE0h〜A3FFFh にあり（BIOS が使う 8 個は A3FE2h から 4 バイトおき。
§12）、実物の VRAM をゲストと共有している。起動時に属性面ごと控え、`-memsw` があればその 8 バイトを
書き込み（`memsw_guest`）、終了時に控えた面を戻す。ゲストが書き換えた値は、ゲストの中だけで意味を持つ
ものとして終了時に捨てる。この領域を消したり詰めたりしてはいけない（§6 の画面消去は見えている範囲だけ）。
ITF がメモリスイッチから導く設定のうち、ゲストの起動に関わるものは §6 で行う。`-memsw` の書き込み自体は
未検証（番地の対応を NP2 の定義に合わせただけで、値を変えて起動した試験はまだ）。

### 値の表記

`-dipsw` の各バイトは、NP21/W の設定ファイル（DIPswtch）と同じ値が同じ意味になるようにする（[spec.md](spec.md)）。
NP21/W 側のビットの並びと ON/OFF の極性は未確認で、実装前に資料か実物で確かめる（§12）。

## 16. 表示系の初期化と復元

ゲストには「電源投入直後」の表示系を見せる。ホストの MS-DOS は 400 ライン・16 色などの状態を残して
いて、200 ライン前提のベアメタルアプリ（イース1・2）はそのままだと縦に潰れた表示になる（§12）。

起動時（`video_guest`）。ホストの BIOS に設定させるので、あとで写す BIOS ワークエリアも同じ状態になる。
BIOS ワークエリアを写す前に行う。

| 項目 | 電源投入時の値 | 設定の仕方 |
| --- | --- | --- |
| グラフィック表示 | OFF | INT 18h AH=41h |
| グラフィックのモード | 640×200（上）、カラー、ページ 0 | INT 18h AH=42h CH=80h |
| CRT モード | 04h（簡易グラフィック属性）+ 40 桁・20 行は DIP スイッチ（SW2-3・SW2-4）に従う | INT 18h AH=0Ah。桁数・行数はホストの現在値の下位 2 ビットをそのまま使う（DIP スイッチの読み出しがまだない。ホストの BIOS が起動時に同じ式で決めた値） |
| テキスト表示 | ON、カーソルなし | INT 18h AH=0Ch、AH=12h |
| 色数 | 8 色（VM にアナログ 16 色はない） | 6Ah ← 00h |
| GRCG | OFF | 7Ch ← 00h |
| デジタルパレット | 恒等 | A8h ← 37h、AAh ← 15h、ACh ← 26h、AEh ← 04h（ポートと番号の対応は §12） |
| テキスト VRAM | 見えている 4000 バイトを空白・属性 E1h に | 直接書く。属性面の末尾はメモリスイッチなので触らない（§15） |

終了時（`video_host`）は、起動時に控えた BIOS ワークエリアの 3 バイト（053Ch CRT モード、054Ch bit 7
グラフィック表示中、054Dh bit 2 400 ライン）から INT 18h AH=0Ah / 42h / 40h・41h を呼び、テキスト表示を
ON、カーソルを ON にし、テキスト VRAM は両面とも 8KB を丸ごと戻す。16 色モードとパレットはホスト側の
値を読み出せないので戻さない（MS-DOS のテキスト画面には影響しない）。

やっていないこと: EGC の状態、GDC の表示開始番地（テキストのハードウェアスクロール）、31kHz の
ホストを 24kHz にすること、グラフィック VRAM の消去（実機のリセットでも残る）。

## 17. スクリーンショット

ホットキー CTRL + GRPH + COPY（VM メニューの項目にもする。[spec.md](spec.md)）で、表示中の画面を 2 つの
PNG にしてホストのカレントディレクトリへ書く。ゲストは撮っているあいだ止まっている（ホスト世界で行う）。

| ファイル | 中身 |
| --- | --- |
| `<名前>###G.PNG` | グラフィック。B・R・G の 3 プレーン（A8000h・B0000h・B8000h）を 640×400 の 4 ビット インデックスカラーに。200 ライン（ゲストの BIOS ワークエリア 054Dh の bit 2 が 0）なら VRAM の 200 ラインを縦 2 倍にする。パレットは、ゲストが書いたデジタルパレットの写し（ポート A8h〜AEh のトラップ。書き込みは実機にも通す）から 8 色 |
| `<名前>###T.PNG` | テキスト。80 桁 × 25 行の文字コードと属性（A0000h・A2000h）を CG ROM のパターン（ポート A1h/A3h/A5h/A9h。§12）で 8×16 のマスに描く。色は属性の G・R・B の 8 色、文字のない画素はパレット番号 8 を tRNS で透明に。反転は塗りと抜きを入れ替え、下線は最下ライン、非表示は何も描かない |

`<名前>` は `-ss` の値（4 文字まで、英小文字は大文字に）、省略時はドライブ 0 のイメージのファイル名の
先頭 4 文字。`###` は 001 から 999 で、G と T の両方が存在しない最小の番号。

PNG は圧縮しない（deflate の stored ブロック。`src/core/png.c`。§12）。1 ファイル約 128KB。書き出しは
転送バッファ（64KB）に溜めてから DOS に渡す。

見ていないもの: グラフィックの表示開始番地とページ（常に VRAM の先頭から）、16 色モード（アナログ
パレット）、テキストの 20 行・40 桁モード、属性の bit 4（縦線・簡易グラフィック文字）、点滅、テキストの
表示開始番地。保存の成否はゲストの画面に出さない（失敗だけコンソールに出る）。

試験: `tests/boot/shotipl.S` が既知の文字（ANK・漢字・反転・下線・非表示）と色の帯を書き、開発用の
`-tick -shotat` で撮った PNG の画素を `tests/run_dos_tests.py shot` が確かめる（PC-98 の環境でだけ）。
文字の形はフォント ROM 次第なので、色と有無だけを見る。
