# 仕様

読者: 開発者・AI。要件と、確定した仕様だけを書く。方式は [design.md](design.md)、経緯は [worklog.md](worklog.md)。

## 目的

フロッピーディスクから直接起動するアプリ（OS を介さないベアメタルアプリ）を、
実機の PC-98x1 上で、ディスクイメージファイルから動かす。

## 動作環境（ホスト）

- 80386 以上の CPU を搭載した PC-98x1
- MS-DOS。CPU がリアルモードの状態で起動する（EMM386 等の仮想86モニタが常駐していないこと。HIMEM.SYS は可）

## 仮想マシン（ゲスト）

- CPU を仮想86モードにし、その中に仮想 PC-98 を作る
- 仮想 PC-98 の構成は基本的にホストと同じ（ハードウェアはホストの実物をそのまま使う）
- フロッピーディスクだけが仮想で、中身はホストのファイルシステム上のイメージファイル

## 機能

| 機能 | 内容 |
| --- | --- |
| 起動 | 指定したイメージを仮想ドライブに入れ、その IPL から仮想 PC-98 を起動する |
| FDD アクセス | アプリの FDD BIOS 呼び出しを仮想86モードで横取りし、イメージの内容で応える |
| ディスク交換 | アプリを一時停止して画面を退避し、ホストのファイルシステムからイメージを選ばせる。選択後に画面を戻して再開する |
| 終了 | アプリを終了させると MS-DOS のプロンプトに戻る |

## 対応ディスクイメージ

| 形式 | 由来 | 拡張子の例 |
| --- | --- | --- |
| FDI | Anex86 | .fdi |
| NFD r0 / r1 | T98-Next | .nfd |
| FDD | Virtual98 | .fdd |
| RAW（ヘッダなし） | SL9821 など | .hdm ほか |

形式は拡張子ではなくファイルの中身で判定する。構造と解釈は [disk-image-formats.md](disk-image-formats.md)。

## 確定事項

| 日付 | 決定 | 前提（これが変わらない限り成立する） |
| --- | --- | --- |
| 2026-10-05 | 初版はリアルモードからの起動だけを扱う。ホスト側への切替口は最初から抽象化し、VCPI 対応を後から差し込めるようにする | VCPI 対応で変わるのが「ホストへ切り替える手段」と「メモリの確保経路」に収まること |
| 2026-10-05 | アセンブリは Intel 記法で書く（gcc-ia16 付属のアセンブラの `.intel_syntax noprefix`） | 付属アセンブラを使い続けること。モニタ核に要る命令が Intel 記法で書けることは確認済み |

## 未決事項

### 外から見える値（決める前に確認する）

後から変えると文書・試験・利用者の手順に波及するもの。

| 項目 | 状態 |
| --- | --- |
| 実行ファイル名 | 未決 |
| コマンドラインの書式（イメージの指定、ドライブ割り当て、オプション） | 未決 |
| ポーズ（ディスク交換メニュー）を呼び出すキー | 未決 |
| ファイル選択で一覧に出す拡張子 | 未決 |
| RAW として受け付けるファイルサイズの範囲 | 暫定（1.25MB / 1.21MB / 1.44MB / 720KB / 640KB の 5 種） |

### 方針（提案つき。根拠は design.md の「未決の設計判断」）

| 項目 | 提案 |
| --- | --- |
| 実装言語 | イメージ解析・FDD BIOS の意味論・ファイル選択 UI は C、保護モードのモニタ核はアセンブリ。C の部分は同じソースをホスト OS 上でも検証する（この前提で着手済み。確認待ち） |
| C コンパイラ | gcc-ia16。生成した DOS 実行ファイルで、ディスクイメージ層の試験がホスト OS 上と同じ結果になることを確認済み |
| ゲストから HDD が見えるか | 見せない（ホストの HDD をアプリから守る） |
| ゲストに拡張メモリを見せるか | 初版は見せない |
| アプリが CPU リセットをかけたときの動作 | 仮想マシンをイメージから再起動する |
| 書き込みの反映 | BIOS 呼び出しのたびにイメージファイルへ書く |
| 仮想ドライブの台数 | 器は 4 台ぶん、既定は 2 台 |
| FDC を BIOS を通さず直接操作するアプリ | 初版は対象外 |
