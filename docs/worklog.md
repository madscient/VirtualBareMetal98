### 2. ホストの調査（NP21/W と実機）

- MS-DOS 起動後の割り込みベクタ表のうち RAM を指すものは、起動時の表示（`redirected:` と `traced to their ROM entries:`）で
  分かる。エミュレータ上の FreeDOS(98)・MS-DOS 5.00A / 6.20・DOSBox-X の内蔵 DOS の分は design.md §12 にある
- シングルステップ追跡による ROM の入口探しは実装済み（[design.md](design.md) §6）。実機の MS-DOS 6.20 / Windows 98 の
  DOS（INT 09h と 1Ah を横取りしている。下の経緯の実機報告）で入口が得られるかは、次の報告のログで見る。得られない
  ベクタがあれば、起動時の `INT xxh enters the ROM at ...` の行（入口と認めなかった入り方）の有無で切り分ける。行が
  あれば design.md §6 の (a)〜(c) に当てはまらない横取りの形なので、その形を調べて足す。行がなければ、ハンドラが
  AX = FF00h では ROM を呼んでいない（追う回数の上限、機能番号の選び方を見直す）

### 7. EMM ドライバとの共存（VCPI）

実装済み（design.md §18）。1 本のバイナリで起動時に判定し（SMSW の PE と INT 67h AX=DE00h）、EMM の下では
VCPI 経由でモード切替する。ゲスト用メモリは XMS のまま（EMM の下でも XMS のロックが返す物理番地がそのまま使えた）。
NP21/W の FreeDOS(98) + HIMEMX + EMM386（NOEMS）で `run_dos_tests.py v86` が通る。残り:

| 項目 | 内容 |
| --- | --- |
| 割り込みの取りこぼし | ホスト世界にいる間の割り込みは EMM 側が受けてホストの IVT へ反射する。こちらの CLI は仮想なので、§7 の「切替を CLI で包む」手では防げない。イース2（60 秒）とソーサリアン（FM 音源、約 75 秒）をリアルモードと EMM の下で比べたところ、割り込みの内訳と INT 1Bh の回数が一致し、症状は出なかった（design.md §18）。症状が出るイメージが見つかったら、ホスト世界の滞在を短くするか EMM 側に割り込みを渡さない手段を探す（§13） |
| MS-DOS の EMM386 で VCPI を有効にする書き方 | NEC の MS-DOS 5.00A の EMM386.EXE は引数なしだと VCPI を提供せず、VBM98 は止まる（確認済み。`run_dos_tests.py msdos`）。引数解析に `VCPI` という語があるが、`/VCPI` も `VCPI` も組み込みに失敗した。マニュアル（利用者の手元に 3.3C と 5.0A の資料がある）か引数解析の続きを読んで書き方を確かめ、VCPI ありの構成の試験を足す |
| 確かめていない構成 | UMB を作るオプション、EMS ページフレームとサウンド BIOS（`-sbrom`）の番地の重なり、MS-DOS 6.2 と 3.3C（3.3C は XMS ドライバが付属しないので別途要る） |
| VCPI のページ確保 | XMS が使えない構成が出たら AX=DE04h の経路を足す（§3 の 3 つ目の経路） |

### 8. D88 形式のイメージ

利用者の要望（2026-10-07）。未着手。D88（拡張子 .d88 のほか .d77 / .d68 / .88d など）は PC-88 / PC-98 系で広く使われる
形式で、配布されている MS-DOS のディスク（3.3C など）もこの形式のものがある。形式の中身は下のとおり記憶で書いて
いるので、着手の最初に資料で確かめて [disk-image-formats.md](disk-image-formats.md) に出典つきで書く。

| 項目 | 内容 |
| --- | --- |
| 形式の確認 | 記憶: ヘッダは 2B0h バイト（ディスク名 17、予約 9、書き込み禁止 1、媒体種別 1 = 00h 2D / 10h 2DD / 20h 2HD、ディスクの大きさ 4、トラックの位置表 164 個 × 4）。位置表が 160 個（ヘッダ 2A0h）の版もある。各セクタは 16 バイトのヘッダ（C・H・R・N、トラック内のセクタ数 2、密度 = 00h 倍密 / 40h 単密、削除マーク、ステータス、予約 5、データ長 2）にデータが続く。1 つのファイルに複数のディスクが連なることがある。出典を確かめ、参考実装（NP2kai の `diskimage/fd/fdd_d88.c`）と突き合わせる |
| 判定 | 決まった署名がない。ヘッダの「ディスクの大きさ」とファイルの大きさ、位置表の値（ヘッダの直後から始まり、単調で、ファイルの中に収まる）、最初のセクタのヘッダの整合で判定する。RAW と取り違えないことを試験で確かめる（RAW は大きさが 5 種に限られるので、先に D88 を試す順にする） |
| ディスクイメージ層 | `src/core/dimg.c` に `mount_d88` とトラックの読み込みを足す（`DIMG_FMT_D88`）。器は合う見込み: 位置表 164 個は `DIMG_MAX_TRACKS` と同じで、セクタごとの C・H・R・N・密度・削除マーク・ステータスは NFD と同じ持ち方ができる。トラックごとにセクタを順に読んで位置を数える（NFD r1 と同じ）。データ長が N と合わないセクタ、0 セクタのトラック（未フォーマット）、位置 0 のトラックの扱いを決める。書き込みはセクタのデータ部へそのまま。書き込み禁止はヘッダのフラグとファイルの属性の両方 |
| 複数ディスク入りのファイル | 最初の 1 枚だけを使うか、選ばせるか。選ばせるなら VM メニューのファイル選択に 1 段足す（外から見える振る舞いなので、決める前に利用者に聞く） |
| 媒体種別 | ヘッダの種別（2D / 2DD / 2HD）を `DIMG_MEDIA_*` に対応させる。1.44MB は種別がないので、2HD でセクタ長 512・18 セクタ以上なら 1.44MB とみなす（FDD 形式と同じ推定）かを決める |
| 試験 | `tools/mkimg.py` に合成の D88（2HD・2DD・不揃いなセクタ・削除マーク・書き込み禁止・壊れたヘッダ・複数ディスク）を足し、ホスト OS 上と DOS 上（`img`）で読み書きを確かめる。fdbios の試験（`fdb`）にも 1 本足す。誤りを 1 つ入れて落ちることを見る（引き継ぎメモの表） |
| 利用者に見える所 | ファイル選択の一覧の拡張子に .d88（と .d77 / .d68 / .88d を入れるか）を足す。spec.md と README の対応形式の表、disk-image-formats.md を直す |
| 実物での確認 | 利用者の手元の D88（MS-DOS 3.3C のシステムディスク）を読めるかを見る。試験の実行環境の起動ディスク（`VBM_MSDOS`）は生イメージだけなので、D88 から生イメージへの変換を試験側に足せば 3.3C も試験に使える（3.3C には XMS ドライバが付属しないので、VBM98 を動かすには別途要る） |

### 9. コードセグメントの残り

本体は small モデルで、コードは 64KB まで。いまの残りは約 8.6KB（`tools/build16.sh` がリンクのたびに表示し、越えたら
止める）。D88 対応（残作業 8）やタイマの復元を足す前に、残りを見て下のどれかを先にやる。「浮く量」は 2026-10-08 の
リンクマップにある部品の大きさを足した見積もりで、実際に外して確かめてはいない（未検証。64 ビット除算や `locale` を
ほかの関数も引き込んでいれば、そのぶんは浮かない）。

| 減らし方 | 浮く量 | 値段 |
| --- | --- | --- |
| 書式の整形を自前にする（`say()` と `menu.c` の `sprintf` が使う `%s` `%c` `%u` `%d` `%X` と桁指定、`l` 付きだけを持つ小さな整形器に替える） | 約 13KB（libc の `svfiprintf` 4.4KB、`locale` 2.4KB、`mbtowc_r` 1.6KB、`wctomb_r` 0.7KB、libgcc の 64 ビット除算 `_udivdi3`・`_umoddi3` 4.5KB ほか） | `log.c` と `menu.c` の 2 箇所。使っている書式を全部洗い出して、整形器の試験をホスト OS 上に足す。表示は全試験が読んでいるので、壊せば試験で分かる |
| `menu.c` の `qsort` を挿入ソートにする | 約 1.2KB | 数行。ファイル選択の並びは自動試験が見ていないので、手で確かめる |
| `strtol` を `optval.c` の 16 進・10 進の読み取りに寄せる | 約 0.6KB | 開発用オプションの引数解析 6 箇所 |
| medium モデルにする（コードセグメントを複数に分ける） | 上限がなくなる | 大きい。C から呼ぶアセンブリの関数がすべて far になり（引数の位置と戻り方が変わる）、ring 0 の C（`_r0.c`）がコードセグメントを 1 つと仮定している所を直す。上の 3 つで足りなくなってから |

### 試験が誤りを捕まえることを確かめた方法

ソースの作業用コピーに誤りを 1 つ入れて試験を走らせ、落ちることを見た。使ったスクリプトは
残していない。試験を大きく変えたら、同じ確認をやり直す。

| 対象 | 入れた誤り | 結果 |
| --- | --- | --- |
| ディスクイメージ層（ホスト OS 上） | NFD r1: リトライぶんのデータを数えない（トラック読込、マウントの 2 箇所）／特殊読み込みのデータ長の位置をずらす／特殊読み込みぶんを飛ばさない。NFD r0: トラック数を 1 減らす／DDAM を落とす。NFD: 1.44MB を 2HD と見なす。FDD: 位置表の要素の大きさを変える／位置 0 をデータなしと見なさない／実体化しても位置表を書き換えない／1.44MB の判定をずらす。一様形式: 片面でもヘッド数 2 で位置を計算する。FDI: サイズの整合を見ない／ヘッダ長を無視する。書き込み禁止を見ない。複数通りのデータの 1 通り目にしか書かない。RAW: 2HC のセクタ数を変える | 17 通りとも、該当するケースが落ちた |
| ディスクイメージ層（DOS 上） | NFD r0 の位置表の位置を `unsigned` で計算する | ホスト OS 上は全件通過、DOS 上は NFD r0 の 6 件が落ちた |
| モニタ核 | ゲートを DPL=0 にする／ゲストを IOPL=0 で走らせる／エラーコードの有無の判定を逆にする | 3 通りとも落ちた。応答なしにはならなかった |
| モニタ核（2026-10-06 の追加分） | 入口で下位 4MB をゲスト向けの写像に切り替えない／トラップした IN AX,DX をバイトとして扱う／DPL=0 のゲートへの INT n を別のベクタへ反射する | 3 通りとも落ちた。1 つ目はゲスト用メモリの試験で応答なしになり、時間切れで検出された |
| モニタ核（HLT と横取り印） | 横取り印の表を違う番地で照合する／HLT で待つ前に IP を進めない | 2 通りとも応答なしになり、時間切れで検出された（FAIL 行は出ない）。前者はリセットベクタの HLT が本物の HLT として待たれ、後者は割り込みのたびに HLT へ戻る |
| ROM の入口の追跡（`romtrace.S`） | far call なら FLAGS の語を見ずに入口と認める／NEC の MS-DOS の INT 1Ah の入り方（design.md §6 の (c)）を認識しない | 前者は `hook` が応答なしになり、時間切れで検出された（DOSBox-X）。後者は `msdos` の 2 項目が落ち、INT 1Ah は印のまま起動した（NP21/W + MS-DOS 5.00A）。追跡そのものを入れる前は `hook` の 09h・1Ah の 2 項目が落ちた |
| ゲストの初期状態（DOSBox-X、`hook`、2026-10-08） | 起動時にゲストの RAM を 0 で埋めない／20h 以上のベクタを差し替えない | 前者は 1 項目（2 回目の起動で前のゲストの値が見える）、後者は 7 項目が落ちた（INT 89h を呼んだ IPL が戻らず、時間切れ）。前者は、最初に書いた IPL の測り方では落ちなかった（埋めないとリセット済みの印も残り、測定を飛ばしていた）ので、測る場所を直した |
| INT 1Bh の意味論の ID の照合（ホスト OS 上、2026-10-08） | C の違う ID を採らない（変更前の動き）／C の違う ID を、合う ID より先に採る／H か N が違っても C の違う ID を採る／C を除いて採った数を数えない | 4 通りとも、該当する項目が落ちた（順に 4・1・2・2 項目） |
| INT 1Bh の意味論（ホスト OS 上） | マルチトラックでヘッド 1 へ移らない／トラック終端の 30h を出さない／ID のシリンダを照合しない／収録ステータスを無視する／能力ビットを足さない／64KB 境界の判定を 64KB ずらす／媒体の種別を照合しない | 7 通りとも、該当する項目が落ちた |

## 経緯

### 2026-10-05

- 要件の提示を受けた。リポジトリは空、16 ビット向けのビルド手段なし
- 4 形式の資料を取得。NFD は配布元のテキストが壊れており、r1 のみ無傷版を別途入手
- 読み比べのため NP2kai のイメージ読込部と FDD BIOS 部を参照した
- 確認した結果: 初版はリアルモード専用、ホストへの切替口は抽象化（確定）
- 実装言語を尋ねたところ「gcc-ia16 は使えないか」と打診された。調べた結果:
  - 公式配布は Ubuntu の PPA と DOS 版。Windows ネイティブ版は公式にはない
  - 開発機には WSL があり、Ubuntu 側に PPA の登録だけがある（本体は未導入）
  - 生成コードは 80286 までの 16 ビット、メモリモデルは tiny / small / medium
  - データが near の 64KB に限られる点について: ディスクイメージ層の常駐データはイメージ 1 枚あたり
    2,792 バイト（ホストの gcc での `sizeof(dimg)`）と共用の作業領域 416 バイトで、4 台ぶんでも
    約 12KB。16 ビット向けに実際にビルドして確かめるのは導入後
- コンパイラに依存しない部分としてディスクイメージ層を先に実装し、ホスト OS 上で検証した
- gcc-ia16 の導入で `apt install gcc-ia16-elf` が「パッケージが見つからない」で失敗した。
  原因は PPA が Ubuntu 18.04 向けの配布をやめていたこと（18.04 向けの索引が空。20.04 / 22.04 / 24.04 向けは配布中）
- 20.04 向けのパッケージ 4 つ（binutils-ia16-elf、gcc-ia16-elf、libnewlib-ia16-elf、libi86-ia16-elf）を
  索引のハッシュと照合したうえで 18.04 上に root なしで展開し、動くことを確かめた。
  binutils は同梱の共有ライブラリを `LD_LIBRARY_PATH` で指す必要がある
- この状態で確かめたこと: DOS 実行ファイルの生成、`__far` と DOS 呼び出しのコンパイル、
  `src/core/` のコンパイル（text 5,302 バイト）、付属アセンブラでの 16/32 ビット混在と特権命令のアセンブル
- printf を使う最小のプログラムが 24KB になった。DOS 側では標準入出力ライブラリに頼らない出力を用意する
- アセンブリは Intel 記法に決まった（確定）。付属アセンブラの Intel 記法で、16 ビットコード内の
  32 ビット版 LGDT / LIDT は `lgdtd` / `lidtd` と書く（`fword ptr` を付ける書き方は通らない）
- DOS の実行環境として DOSBox 0.74-3 と NP21/W（FreeDOS(98) の起動イメージ、ホストのフォルダを
  ドライブとして見せる HOSTDRV、エミュレータを終了させる PWOFF つき）が用意された。
  DOSBox 0.74-3 は PC-98 を再現しないので、機種に依らない範囲の確認に使う
- 試験プログラムをホスト OS と DOS の両方でビルドできる形に直し、DOS 用の入出力層を書いた。
  DOSBox を画面なしで起動してバッチを流し、結果ファイルを回収する形で 39 件が通った（約 80 秒）
- DOS 上の試験が 16 ビット固有の誤りを捕まえることを確かめた。位置の計算を `unsigned` で行う
  誤りを入れると、ホスト OS 上は全件通過、DOS 上は NFD r0 の 6 件が失敗した。
  同じ誤りを型変換なしで書いた場合は、ホスト OS 側のコンパイル時の警告で先に止まった
- モニタ核の最小版を書いた。アセンブリはモード切替と例外の入口・出口だけにし、判断は ring 0 で
  動く C に任せる構成にした（design.md の D8）。DOSBox 上で 25 項目が通った
- その過程で分かったこと:
  - gcc-ia16 の通常のコードは保護モードで動かない。32 ビット値の読み込みに LES を使うなど、
    セグメントレジスタを値の置き場にする。モニタ内で一般保護例外になり、エラーコードが
    「ゲストの IP の値」だったことから判明した。`-mprotected-mode` で解消した
  - ring 0 の C から C ライブラリやコンパイラの補助関数を呼ぶのも同じ理由で避ける。
    ビルドに外部参照の検査を入れたところ、構造体の代入が `memcpy` の呼び出しになっているのを
    その場で捕まえた
  - gcc-ia16 は ES を「呼ばれる側が保存するレジスタ」として扱う。モード切替の関数が ES を
    壊していたため、呼び出し側の変数（文字列へのポインタ、セグメント値）が化けた
  - 最初の版は DOSBox が応答しなくなった。上の 2 点を直したあとは再現していないが、
    どちらが応答なしの直接の原因だったかは切り分けていない
- 切り分けには、モニタ内で例外が起きたときにスタックの内容を控えて返す仕組みが効いた。
  これは `mon_panic_get` として残してある
- モニタ核の試験が誤りを捕まえることを確かめた。ゲートを DPL=0 にする、ゲストを IOPL=0 で
  走らせる、エラーコードの有無の判定を逆にする、の 3 通りでいずれも試験が落ちた
- MS-DOS Player（コンソールで DOS プログラムを直接走らせるもの）も置かれていたが、標準入出力を
  パイプにして起動すると引数なしでも戻らなかった。原因は調べていない。DOSBox で足りたので使っていない
- 別のマシンで続けられるように、環境の準備手順を [setup.md](setup.md) に、残作業と引き継ぎメモを
  この文書に、INT 1Bh について読み取ってあった事実を [design.md](design.md) §8 に書いた。
  それまでは開発機の上にしかなかった情報である

## 見送った提案

| 提案 | 見送った理由 | 見直す条件 |
| --- | --- | --- |
| ホスト側もすべてアセンブリで書く | イメージ解析と UI を実機／エミュレータ上でしか検証できなくなる | — |
| C コンパイラに Open Watcom を使う | gcc-ia16 の打診を受けて保留。gcc-ia16 はホスト検証用の gcc と同じ方言で書ける | gcc-ia16 で DOS 向けのビルド・リンクが成立しなかった場合 |
| モニタ核を NASM で書く | gcc-ia16 付属のアセンブラで必要な命令がアセンブルできると確認できた。ツールが 1 系統で済む | 付属アセンブラの記法や機能で困る点が出た場合。その際は NASM のオブジェクトをリンクできるかを先に試す |
| `-sbrom` でサウンド BIOS の INT D2h も登録する | IPL がヘッダ（CC000h + 2E00h）をどう読んで登録するかが資料から読み取れず、推測で書くと誤った登録になる。ROM を見せるだけで足りるアプリを先に対象にした（design.md §12・§15） | 登録が要るアプリが見つかり、手順を資料か実機で確かめられたとき |
| 18.04 に 20.04 向けパッケージを依存関係を無視して入れる | パッケージ管理が不整合な状態になる。展開するだけで動くと分かったので不要 | — |
| イメージ全体を起動時にメモリへ読み込む | 1 枚 1.2MB 前後 × ドライブ数の拡張メモリが要る。書き戻しの時機という別の問題も生む | BIOS 呼び出しごとの世界の切替が遅すぎると分かった場合 |
| ホスト世界も仮想86モードで動かす | ホストの常駐物やディスク BIOS が使う特権操作を、モニタがすべて代行することになる | — |
| BIOS の横取りにデバッグレジスタを使う | エミュレータ側の対応状況が未確認。本数も 4 本に限られる | — |
| RAW に 256 バイト × 26 セクタなどのサイズを加える | 要件にあるのは標準的な媒体。同じサイズで構造の違う形式があり、拡張子に頼る判定が必要になる | 該当するイメージを使いたいという要望 |
| NFD r0 の仕様書の無傷版を機械的に取りに行く | 保存サイト側で自動取得として拒否された | 手元のブラウザで取得できたら、欠けた説明文と突き合わせる |
| V30 を命令単位の解釈実行で再現する | 仮想86モードで直接実行する速さが失われる。固有命令が例外になることを利用すれば、ほとんどの命令は直接実行できる | 例外にならない差（プリフィクスの意味、シフト回数のマスクなど）に依存するアプリを動かす必要が出た場合 |
| ゲストの割り込みマスクの既定でスレーブの IR7 を閉じる（スプリアス 17h を消す） | 電源投入時の値（71h）から外れる。原因はホストが残した保留要求で、ゲームの動作は妨げていない | 実機でも出ると分かった場合、またはスプリアスの処理時間が問題になった場合 |
| 起動時にテキスト VRAM を両面 8KB 全部消す | 属性面の末尾にメモリスイッチがある。見えている 4000 バイトで足りた | ゲストが表示開始番地を変えて残りの領域を見せる場合（そのときも末尾 32 バイトは避ける） |
| FDC（μPD765）の直接アクセスをエミュレートする | 3 本の実イメージは INT 1Bh だけでディスクを読み、FDC のポートには触れなかった（`-traceio` で確認）。ソーサリアンは自前の FDC 割り込みハンドラを持つが、確認した範囲では使っていない | FDC を直接叩くアプリに当たった場合。DMA（8237）の代行も要るので値段は大きい |
| スクリーンショットの PNG を圧縮する | deflate の符号化（LZ77 とハフマン）を 16 ビットの C で書くことになる。圧縮なしで 1 枚約 128KB、2 枚で 256KB なら用は足りる | 枚数が増えて容量や書き込み時間が問題になった場合 |
| テキストのフォントを BIOS（INT 18h AH=14h）で読む | NP21/W のホスト世界では何も返らなかった（design.md §12）。CG ポートで読めば BIOS に依らない | 実機で CG ポートの読み出しが期待どおりでないと分かった場合 |
| ホットキー (COPY) のスクリーンショットの保存を画面で知らせる（音・表示） | ゲストの画面を汚さない方法がない。メニューから撮ったときは知らせを出している | 要望があれば、短いビープ音を検討する |
| VM メニューのあいだグラフィック画面を消す | ゲストが表示をどう設定したか（INT 18h か GDC 直接か）を追っていないので、戻すときに間違える。文字を重ねるだけでも読める | GDC のコマンドポート (A2h) を追う仕組みを入れた場合 |
| VM メニューで消したテキスト表示を、ゲストの状態に戻す | 同上（ゲストの設定を追っていない）。開くときに ON にしたままにしている | 同上 |
| 罫線の枠を ASCII で描く | NP21/W の生成フォントで JIS 8 区が見えないのはエミュレータ側の都合で、実機では見える見込み | 実機でも見えなかった場合 |
| ROM の入口を「最初に ROM に入った番地」で決める | ホストのハンドラが ROM の途中へ飛び込むことがある（NEC の MS-DOS の INT 1Ah）。その番地をゲストに渡すと割り込みのたびにスタックが壊れる | — |
| 入口を追う対象に INT 1Fh（拡張 BIOS）を入れる | 拡張メモリを使う機能があり、ゲストには拡張メモリを見せない。ROM へ渡すとホストの拡張メモリ（ゲスト自身が載っている）に触れる | 1Fh の機能のうち安全なものだけを代行する形にするとき |
